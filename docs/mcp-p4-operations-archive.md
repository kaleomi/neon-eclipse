# P4 第一批：独立只读行动档案

## 范围与入口

用户要求在 P1 并行开发期间先做 P2–P4 中不冲突的工作。本批选择 P4 本地战斗档案，**实现只新增独立文件**，已有文件仅追加文档索引与进度记录，不修改 app.js、主菜单、战斗、Boss、地图接线、package.json、SaveHub 或 telemetry.js，不改存档格式、不制作 EXE、不 Git 提交。

入口：在现有游戏服务的同一站点打开 `operations-archive.html`（例如将 `index.html?...` 换为 `operations-archive.html`）。必须使用保存战斗记录的同一浏览器、同一站点和端口；其他浏览器/端口看不到原有 IndexedDB。这次没有改主菜单，页面提供“返回游戏”链接。

## 已交付

- 只读访问 `neon-eclipse.telemetry.v1 / attempts`，使用现有遥测记录和地图名称注册表。
- 章节、难度、单章/旅程/训练、检查点恢复、近7/30/90天筛选与重置。
- 行动数、胜负、记录胜率、阶段活动时间及射击数；章节最好时间、失败最多阶段。
- 原八槽的可用分枪射击与未分类射击条形图；刀动作不冒算枪械射击。
- 每页20条行动记录；筛选结果 JSON 下载，明确区别于游戏存档备份。
- 霓虹工业深色面板、层次阴影、键盘焦点、390px窄屏布局；空记录、无匹配、拒绝访问、超时及未知数据库版本均有提示。

## 数据真实性与隐私

- 只有从章首开始、非训练、未从检查点恢复的胜利才进入最好时间。不同难度需筛选后比较。
- 不把阶段训练当整章通关；不把多次恢复的累计时间、击破相加冒充生涯记录。
- 阶段活动时间来自已记录阶段，不等于总在线时长。未结束、关闭遥测前后缺失、写入失败的行动不能恢复。
- 重武器可能只计入总射击而无分枪数组，归入未分类；刀动作不计枪械射击，零值不代表未使用。
- 没有可靠字段的命中率、各枪击杀、载具里程、成就完成率和六维能力不伪造、不补写。因此本批不是完整 Profile、称号或雷达图系统。
- JSON 导出仅包含筛选后的统计投影，不含死亡坐标；不提供导入、删除、恢复或写入按钮，不上传数据。
- 空数据库采用升级事务立即取消的兼容读取方式，不留下新数据库；已有数据库只用 readonly 事务，未来数据库版本不迁移。连接在读取完成/失败时关闭，超时后到达的连接也关闭。
- 最多处理2000条，超量、无效、未知和重复条数明确提示；未知地图名称以文本显示，不注入 HTML。

## 测试

新增 `test-archive-summary.mjs`、`test-archive-reader.mjs`、`test-archive-browser.mjs`，由既有测试运行器自动发现，无需修改 package.json。

规则测试：筛选、缺失/未来/坏数据、重复与2000条上限、特殊地图键、最好时间资格、刀动作排除、无坐标导出、输入不变；存储不可用/拒绝/超时/未来版本、取消新库创建、readonly事务与关闭连接。

浏览器测试自行启动并关闭独立临时服务器和隔离 Chromium：空记录不留新库、27条有效测试数据与未知记录、筛选、20条分页、真实JSON下载、HTML字符串仅作文本、390px无横向页面溢出、键盘焦点、拒绝访问/未来版本。监控 localStorage 和 IDB 写方法，筛选/读取/导出零写入；真实读取回原始测试记录逐项等价，存档哨兵保留。

截图使用隔离的合成测试数据，不是用户真实成绩；不是实机游戏性能验收。只运行本批专项，不声称全项目或 P4 全部通过。
