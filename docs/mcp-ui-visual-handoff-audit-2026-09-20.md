## 3. 视觉评估

### 值得保留

- 深蓝黑底、低饱和薄荷青强调、轻边框的方向一致，不建议推倒重做或改成高亮霓虹。
- 主菜单行动列表与章节主视觉已有基础；设置分类优于长页堆叠。
- 复用真实控件和存档模型，避免再建一套只具外观的控件。

### 优先问题与风险

1. 主菜单视觉重心：既有截图右侧主视觉起点偏低，右上留白较大；品牌识别弱于宣传文案。建议提高章节画面占比并重新对齐标题、行动列表与视觉主体。
2. 行动优先级：截图无存档状态下，禁用继续与战备整备位于新游戏之前。建议无档以新游戏为首，有档以继续为首；视觉排序与 DOM/键盘顺序须一致。
3. 可读性：截图中辅助文字、页脚与部分导航偏小偏暗。源码存在 8–11px 信息字号；建议主要正文 14–16px、必要辅助信息 12–13px，并实际测量对比度，而非宣称已经不合格。
4. 设置布局：全局侧栏叠加分类侧栏占用较多宽度；保留分类逻辑，优化间距、行高与阅读宽度，不为装饰再加一层卡片。
5. 焦点风险：ui-clean.css:83 对菜单多种可交互元素的 focus/focus-visible 统一 outline:none!important。主菜单有替代高亮，但其他控件需逐项检查，不能直接认定全部不可访问。
6. 样式维护：ui-clean.css:41–65 与 71–117 对主页重复定义，混合高优先级选择器和 !important；102 行 background:none!important 与 307–315 行同元素背景图规则冲突，后者在该层叠关系下不能生效。后续应合并职责，而非持续追加覆盖。
7. HUD、装备、结算与动态 3D：本轮未查看实时画面，属于待实测范围，不捏造具体遮挡或性能缺陷。

## 4. 推荐接手路线（尚未实施）

### 第零批：固定基线

确认并行编辑边界，记录待改文件哈希；在隔离浏览器上下文采集首页、章节、七类设置、装备、工坊、HUD、暂停和结算。保留用户存档与原服务来源。

### 第一批：主菜单与章节选择

保留简洁科幻方向，优化品牌、主视觉、行动优先级、章节图片裁切及锁定/已完成/当前状态；把这一批作为风格定稿，不一口气改全套。

### 第二批：设置与装备

统一字体、间距、按钮、表单与焦点规范；优化设置双栏密度和工坊信息分组；不改变真实配置、解锁、重开确认与持久化语义。

### 第三批：HUD 与暂停结算

优先保证准星区域与战斗可读性，核验生命/弹药/目标/危险反馈层级，标准和精简 HUD 均保留；暂停与结算主按钮始终可见可点击。

### 第四批：3D 场景表现

先以反应堆单章建立材料、曝光和灯光标杆，再评估其他章节。确保敌人与可交互物辨识度；未经确认不动战斗数值、碰撞、导航、关卡流程与音频。

## 5. 验收标准

- 视口建议覆盖 1920×1080、1440×900、1280×720、1024×640、390×844；检查必要内容与主操作，窄屏 UI 通过不代表触屏战斗已支持。
- HUD 80%/100%/115%，中文长名称、英文、无档/有档/受保护存档；键盘 Tab、Enter、Esc 与减少动态效果。
- 普通信息文本对比度以 4.5:1 为目标，大字及必要非文本控件以 3:1 为目标；禁用态按语义单独处理。
- 当前源码重跑 test-ui-clean-browser.mjs、test-ui-clean-layout-browser.mjs、test-ui-clean-live-browser.mjs，以及 smoke；检查实际控件行为而不是仅改变测试去追求通过。
- 3D 另做固定镜头前后对比与相同硬件/画质下帧耗测量；静态截图与规则测试不替代性能验收。
