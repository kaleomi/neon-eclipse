## 低负载验证纪律

- 文档整理不触发完整回归；日常仅跑相关语法/规则，**一次一个进程**。
- 本轮未改 runner 的默认 jobs=4；今后经用户同意跑完整套件时使用 `npm test -- --jobs 1`。这减少并发，不是 CPU 硬限额。
- 浏览器脚本使用 SwiftShader 可能占用大量 CPU；本轮不启动浏览器自动测试。专项也须与其他测试、试玩错开。
- MCP 命令短等待返回，再查询同一 command_id；结果不明先核对旧进程，不重复启动，不终止用户试玩服务。
- 日志记录失败和复测分别的版本/返回码；受控时钟通过不替代原实时流程、人工或性能验证。

## 回退原则

使用追加式 `git revert`，不 `reset --hard`、不清理工作区、不重写用户历史。先暂停其他写入者并备份/提交相关工作，再按本轮依赖从后向前回退；单独撤回音频基础而保留依赖入口会破坏运行。回退源码不代表降级玩家存档；旧版本应拒绝不支持的新 schema，先导出备份并用隔离配置验证。
