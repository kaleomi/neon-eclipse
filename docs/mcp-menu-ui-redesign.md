# 首页、选关、设置与下一关 UI 重构

日期：2026-09-17

项目：`game/b4cac37d-4fa9-4d31-8c30-d07e3ee813a6`

## 用户需求与范围

首页信息过多，要求明确分为新游戏、继续游戏、选择关卡、设置；章节之间的界面需要让玩家一眼看清应该点击哪里。

本轮重做菜单、选关、设置、暂停、结算及续关界面，不重做战斗 HUD，不修改关卡玩法和战斗数值。

## 已实现的交互

### 首页仅保留四个主入口

| 入口 | 行为 |
| --- | --- |
| 新游戏 | 开始六章连续战役。已有战役记录时弹出明确的覆盖确认；取消与 Esc 不写入存档。当前已在第一章时可直接开始，否则前往第一章准备页。 |
| 继续游戏 | 优先恢复当前暂停中的战斗；否则继续有效战役。无有效进度时禁用并解释。仅有单章进度时提供对应继续入口；存在多个单章检查点时明确列出，不擅自猜测最近的一个。待保存章节结果优先处理。 |
| 选择关卡 | 独立页面展示六张带章节编号、示意图和玩法摘要的卡片。单章模式与连续战役保持分离。阶段训练收进二级区域。 |
| 设置 | 独立页面集中展示画质、HUD 开关和幅度、UI 缩放、密度、瞄准灵敏度与操作说明；不再挤占首页。 |

- 首页继续入口展示将要恢复的章节/模式，避免“继续游戏”指向不明。
- 记录、星星及单章挑战保留在独立的“记录与荣誉”页面。
- 新增本地矢量章节示意图，无外部图片或字体服务依赖。
- 菜单保留实际游戏场景作为背景；打开菜单时隐藏外围战斗 HUD。

### 下一关只有一个明确的推进操作

- 章节结算页展示“本章已完成”、下一关名称、用时/击破统计和六章进度。
- 大号主按钮固定命名为“进入下一关”，附带具体章节编号及名称。
- 点击后保存下一关入口并直接切换页面，停用原先再次弹出过场、再点一次进入的调用链。
- 新关卡载入后用同一位置的大按钮“开始本关”或“继续游戏/继续本关”进入战斗，便于浏览器取得鼠标锁定，不再显示一排互相竞争的开始入口。
- 独立单章通关也可前往下一关，但不会擅自推进或覆盖连续战役。
- 第六章结束显示结束/返回主菜单，不生成不存在的第七章。
- 阶段训练结算仍为“再次训练本阶段”，不会被当作章节通关。

### 暂停、失败与存档保护

- 暂停主操作为“继续游戏”，原地恢复内存中的战斗，不重新载入检查点。
- 从暂停进入设置、查看记录或返回主菜单不会自动重置战斗；返回主菜单后的继续入口仍优先恢复当前暂停会话。
- 失败主操作为“从检查点重试”；没有检查点时明确重新开始本关。
- 重试阶段、重开已有单章或覆盖战役有对应提示/确认。
- 战役结果保存失败时显示“保存结果并进入下一关”或“重试保存战役结果”；保存未成功不能跳关。
- 结果已保存但下一关入口写入失败时保留章节间状态，允许重试，不提前导航。
- 跳转中设有重复触发保护，避免连续点击跳过章节。
- 选关切换页面前提示暂停战斗只能从阶段入口恢复；有待保存章节结果时引导先完成保存。
- 存档发现只读取现有键，不进行修复、删除或隐式迁移写入。

### 设置与可访问性

- 画质改为性能/均衡/精细三选一，而不是隐藏在长菜单中的循环按钮。
- 沿用既有 `neon-eclipse.presentation.v1` 显示偏好。
- 灵敏度额外使用独立 `neon-eclipse.controls.v1` 保存，默认及有效范围仍为原来的 1.0 和 0.5–2.0，不改瞄准算法。
- Tab 焦点、Enter 按钮确认、Esc 返回、覆盖确认的焦点约束和取消操作已接入。
- 覆盖确认默认聚焦取消；表单键盘事件不会触发战斗输入。
- 窄窗口允许二级内容滚动，不要求首页或下一关主按钮藏在长列表底部。
- 支持系统减少动态效果。

## 主要文件

- `menu-state.js`：章节展示元数据、只读单章存档发现、继续目标及唯一主操作的纯逻辑。
- `menu-ui.js`：四入口首页、页面导航、暂停/结算、确认与键盘焦点管理。
- `menu-art.js`：本地 SVG 图标与六章示意图。
- `menu.css`：独立菜单布局和响应式样式，不套用旧 `mission-card` 的堆叠规则。
- `app.js`：菜单接入、主按钮分发、直接续关、跳转锁及保存失败反馈；少量旧状态节点保留供现有逻辑使用。
- `combat-ui.js`：原灵敏度控件继续复用，补充独立设置持久化。
- `index.html`、`package.json`：加载菜单样式，接入新测试。
- `test-menu.mjs`：菜单状态、存档发现及跳关分支回归。

原 `journey-ui.js` 文件保留，但运行入口不再调用旧战役菜单与二次过场；没有为了清理文件而额外删除历史模块。

6. 新游戏覆盖确认的取消、Esc、写入失败和重试；旧星星与荣誉不被清空。
7. 章节结果写入失败不跳关；成功重试仅登记一次结果。

9. 多个单章存档的选择、死亡重试、阶段训练不误推进章节。

## 保持不变与使用提示

- 关卡路线、隐藏星星难度、Boss 血量、武器伤害、成就条件和既有存档迁移规则不变。
- 没有安装/升级原 Windows 项目的依赖，没有初始化 Git，没有清空或读取用户真实浏览器存档用于测试。
- 只在隔离环境安装浏览器测试工具；没有在用户主机额外启动游戏服务器。
- 现有静态服务器无需修改。刷新游戏页面加载新模块；若正在战斗，先完成当前阶段再刷新，避免丢失检查点之后的现场状态或当前一命挑战资格。
