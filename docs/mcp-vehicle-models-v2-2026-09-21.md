## 同源与生命周期

核对发现，原 `vehicle-models.js` 的 GLB 生成器与驾驶页 `vehicle-world.js` / `sea-air-world.js` / `helicopter-world.js` 各自维护一套几何。旧清单虽然写同源，但实际调用关系并非如此。本批让这三个适配器真正委托 `createVehicleVisual`。

- 原车身地形倾斜/颠簸、四轮地面高度、转向和行程轮转公式保留；挂接炮塔的父节点矩阵继续一致。
- 原飞机 YXZ 姿态、油门螺旋桨率及坠毁状态公式保留。
- 原快艇波动/转向倾侧公式、敌方识别与 wake 句柄保留。
- 原直升机俯仰/横滚、旋翼角、尾桨三倍角及 RPM 模糊切换保留。骨骼自身 visibility 不会隐藏已合批顶点，因此在同一旧阈值下把桨叶骨骼缩为零；静态导出保持正常比例。
- `disposeVehicle` 幂等释放几何、材质与骨骼贴图；原直升机对象释放器补充去重的 skeleton.dispose。没有引入这些 GLB 的生产网络请求。
- 构建器默认真实比较二进制、完整单件清单和总清单；记录模型源及构建器哈希，不再仅比一部分字段。

## 失败与测试夹具修复（全部保留证据）

1. 本地格式预检发现 V01 关节需要共同根、静态快艇多余空节点、无发光材质的冗余发光强度声明。补共同 RigRoot、移除空节点、使用默认非发光强度后再导出；最终精确 GLB 校验全部为零。没有调整 Validator 严重级别或忽略问题。
2. 首轮展厅/Node 通过不等于外观签收。渲染检查后的几何修正已重新导出，模型 Node、新姿态测试、直升机包络和新浏览器全部再次通过；首轮图、源和清单留在 `visual-pass1/`。
3. 原直升机场地测试的 150ms 右键脉冲未触发火箭。改为按住到同一个原 5 秒条件满足，再 finally 松开；没有改游戏或放宽断言。该次失败不能确定所有调度时序根因。
4. 随后旧测试直接点击现已折入分类页签的灯塔按钮，因不可见超时。改为正常点击“任务 → 灯塔”页签后仍点击原启动按钮两次；没有 force click 或改 DOM。
5. 独立直升机旧测试假定暂停层仅有两个焦点按钮。当前 UI 已有页签与 H-02 链接；第一次适配仍只枚举按钮而漏掉链接，继续失败。最终改成枚举所有当前可见、可聚焦控件，并验证完整正向循环和反向边界；不改变生产菜单。完整可聚焦控件循环最终通过。
6. 恢复飞行后的 WebAudio 状态更新是异步的，旧测试在 100ms 后立即断言，遇到 suspended。增加与它原先首次开启音频时相同的最多 20 × 50ms 状态等待，仍必须断言 running；未改音频或游戏实现。最终独立原型浏览器 10/10 通过。
7. 临时外网预览地址没有定位到目标页面控件，不算离线包通过；转而复制精确文件并以 file:// 断网复验通过。一次上传超过 Bridge 单次 262,144 字节上限而被拒绝，随后拆为小块并在解压后核对整个 HTML 的哈希；没有改变交付内容。

旧 `test-helicopter-field-browser.mjs` 与 `test-helicopter-browser.mjs` 都有逐字节备份。三份生产几何适配器、一个模型源和构建器是实质代码改动；两个旧浏览器文件及一个旧 Node 文件只用于准确适配验收，没有把测试修复当成新增游戏功能。
