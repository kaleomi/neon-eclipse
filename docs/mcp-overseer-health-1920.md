# 枢纽监察者四倍血量与交付约定

## 本轮修改

按“原来的 4 倍”执行：第三章枢纽监察者核心生命从 480 提升至 1920；第二阶段仍为半血触发，即 960。第一章 Warden 未修改，两座供电节点仍各 65 HP。攻击伤害、频率、暴露时间、守卫数量和补给不变。

新增 `OVERSEER_MAX_HP` 作为单一配置，初始状态、重试、阶段阈值、UI 数值与血条比例统一读取，避免血条仍按旧值计算。旧地图 / 战役检查点结构不变；重新加载本阶段时 Boss 按新生命重置。

## 验证

`npm test` 全部通过。新增 1920 初始生命、961 时保持第一阶段、960 时进入第二阶段、重试复位与节点血量不变的断言；Three.js 无渲染 UI 测试验证满血显示 1920 / 1920、半血显示 960 / 1920 及 50% 血条。

回归发现旧 AI 下楼测试会受随机攻击节奏影响：敌人下楼后可能因后退战术重新踩上首级台阶，因此不能只检查最后一帧脚部高度。改为记录测试期间确实到达地面并退出台阶碰撞范围；保留严格的下楼要求，未修改 AI 行为。全套及额外重复 AI 测试通过。

四倍血量会提高弹药需求与节点循环次数，本轮未进行新版完整人工通关或实机性能评估。

## 持续交付约定

用户要求：以后每次完成开发，自动说明本轮完成内容、验证结果和接下来的开发方向，无需用户重复提醒。

## 后续优先顺序

1. 试玩 1920 HP Boss：记录击杀用时、暴露轮数和弹药余量。保持用户指定核心血量，必要时优先讨论补给与暴露窗口，而不是擅自降低血量。
2. 多守卫楼梯让行与压力测试；增加高低层雷达提示。
3. 运输区呼叫按钮、完整护栏和检修支线目标；再确定敌人登车规则。
4. 地下站真实移动列车：车厢承载、站台连接、安全车门及暂停 / 读档恢复。
5. Boss 音效与演出、三章完整平衡和实机帧时间优化。
