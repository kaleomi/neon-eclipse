日期：2026-09-20。

## 交付范围

用户确认先做敌人样板。本批只替换普通远程守卫 `ranged` 的表现层，不扩展到其他兵种、Boss 或主角手臂。

- 原创科幻硬表面装甲：分层胸甲、切面头盔、紫色光学面罩、护肩、膝肘关节、背部散热模块、天线和持枪组件。
- 冷色合金、浅色陶瓷装甲、深色柔性连接件与紫色兵种识别光。当前是偏机械装甲、低多边形切面的第一版，不宣称电影级真人或照片写实效果。
- 真实 GLB 资源，含 Idle / Patrol / Aim / Hit 四个动作片段；使用 13 个刚性活动节点，不是 SkinnedMesh 人体蒙皮。
- 游戏内姿态由现有移动/蓄力状态和生命变化驱动；预览页直接播放 GLB 中的动画片段。
- 独立预览支持轨道旋转、缩放、正面/四分之三/背面、四个动作、线框、暂停、自动旋转、曝光与 GLB 下载。

## 文件与使用

| 文件 | 用途 |
| --- | --- |
| `characters/ranged-guard.js` | 可复现的程序建模、材质、节点姿态、动画导出及实例资源管理 |
| `characters/ranged-guard-runtime.js` | GLB 缓存、逐实例克隆、加载回退、命中代理适配和游戏动作 |
| `scripts/build-ranged-guard.mjs` | 只生成本样板资产与清单 |
| `models/ranged-guard-r07.glb` | 可直接导入支持 glTF 2.0 软件的三维资源 |
| `models/ranged-guard-r07.manifest.json` | 面数、材质、动画、文件哈希与源码哈希 |
| `enemy-ranged-preview.html`、`enemy-ranged-preview.js` | 独立交互预览 |
| `test-ranged-guard.mjs` | 几何、命中、动画、GLB 和资源生命周期测试 |
| `test-ranged-guard-browser.mjs` | 隔离浏览器中的预览与真实游戏接线验证 |
| `enemy-model.js` | 原有文件中的小范围适配接线，保留本轮开始前已有的 PBR 改动 |

使用项目现有开发服务器，访问同一站点下的 `enemy-ranged-preview.html`。例如默认 `npm run dev` 使用 5173 端口时，对应路径为 `/enemy-ranged-preview.html`。不要用 file 协议直接打开依赖 ES modules 的页面。

重建和验证：

```bash
node scripts/build-ranged-guard.mjs
node test-ranged-guard.mjs
node scripts/run-tests.mjs --layer browser --filter ranged-guard --jobs 1
```

未在用户机器安装新软件或依赖；使用了项目现有 Three.js、Node 和外置 Playwright 工具。没有提交、推送、打包或发布。

## 实际资产规模

- 7,768 个三角面。
- 8 种 PBR 材质，72 个合并后的网格批次；合并限于同一动画节点和同一材质，不跨关节。
- 4 个动画，每段 14 条节点轨道。
- 项目内生成的 GLB 为 892,920 字节，约 872 KiB。
- 无图片贴图、无外链贴图、无外部 GLB 依赖；金属/粗糙度等由 PBR 材质参数控制，不冒充已完成烘焙贴图流程。
- GLB SHA-256：`18fd9cc4fa2716076a2f30c6e7eff46ca88fa664e8401194167b1bc59c59b177`。
- 模型源码 SHA-256：`f9bd2c9d404f7b9f6f712d74039408a511e11699125be91d2f0e22aad58c08b0`。

同一来源在不同 Node/V8 平台构建时，浮点 JSON 序列化可能产生字节差异；以各次清单中的源码哈希、GLB 哈希和重载测试为准，不承诺跨运行时逐字节相同。

## 战斗兼容与加载设计

1. 原远程守卫的直接子级 Mesh、几何、位置、原有手脚摆动和 `hitZone` 均保留，隐藏的是绘制而非射线判定。新可见模型作为独立子树，不参与战斗射线。
2. 因而旧的非递归射线、直接父节点归属、近战接触和身体/头部查询接口仍可使用。美术附件不是逐三角形精确命中体，装饰件与旧代理轮廓存在一定差异。
3. 不改生命、伤害、射程、碰撞半径、攻击时机、寻路、存档格式；保留紫色蓄力提示及指挥官增益的发光逻辑。
4. 先同步提供同源程序模型，GLB 完成后替换为缓存资产的逐实例克隆；GLB 缺失、延迟或损坏不阻止敌人生成或受击。
5. 实例的几何和材质独立，复用本敌人的角色识别材质；销毁一名敌人不影响其他实例。延迟回调检查是否仍在场景中，不复活已销毁/重开的旧实例。
6. GLB 请求在模块内共享。当前仍有瞬时程序模型创建/替换开销；本批没有将大量同屏性能或 LOD 优化宣称完成。

- 使用临时静态服务器和新 Chromium 上下文，不触碰玩家真实 localStorage、IndexedDB 或浏览器配置。
