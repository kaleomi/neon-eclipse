已读取当前 `frame-stats.js`：

- 最多保留 4096 个帧间隔样本，达到上限后只增加丢弃计数。
- 汇总的 `frames` 包含已丢弃数量，但百分位和平均值基于保留样本。

这些采样边界本轮保持不变，已在档案页解释；仅修正只读汇总权重。后续若需要全程/分画质/排除暂停的精确统计，应另立兼容增量，先补测试，再选择有界采样策略。如需扩展持久化元数据，采用可选字段并验证旧记录，不改写历史成绩或存档资格。

## 实机验收：仍需单独完成

自动化使用 SwiftShader，不能代替用户显卡上的实测。建议在隔离浏览器配置、单标签页中进行：

1. 记录 CPU、GPU、内存、浏览器版本、分辨率、DPR 和画质。
2. 每档预热后固定路线，覆盖入口、核心附近、交火、特效、暂停恢复和重试。
3. 每档持续 10–15 分钟，记录采样覆盖时长、P50/P95、最长帧及异常场景；软件渲染结果与硬件结果分开。
4. 对照修改前后同一场景，不以一次截图上的 FPS 或单次耗时承诺性能提升。
5. 帧率目标与最低硬件配置在获得实测数据后确定，不先宣称“稳定 60 FPS”。
