# P1 第一批交付：ARC BLADE 短弧与打击窗口

日期：2026-09-17  
依据：`docs/mcp-full-development-plan.md` 第 5.1 节。用户将 P0 分配给另一位 AI，本批只接手 P1 战斗相关源码，不制作 EXE。

## 交付边界

**这是 P1 的第一批，不是整个 P1 完成，也不是处决/弹反已经实现。**

核对最新源码后，发现原近战已经有 21 条、水平 ±18° / 垂直 ±7° 的补偿射线，不能按照开发方案中较旧的“单射线”描述重复施工。

本批完成：

- 在 0.42 秒挥砍动作的 **28%–58%** 区间逐更新探测。第一帧没有碰到目标，不再立即消耗整次挥砍；窗口内稍后进入的目标仍可命中。
- 空间采样改为 **水平 ±35° / 垂直 ±15°、5×3 基础射线**。近处目标的包围盒最近点、中心最多各提出一条补偿方向，减少小目标落在基础射线间隙的漏判。
- 补偿方向也必须满足角度和距离限制，并取得真实三角面首个交点。包围盒本身不算命中，不越过遮挡物；中心命中继续优先，命中部位取实际交点。
- 保留可见网格遮挡、碰撞体遮挡、相机陷入墙内时拒绝攻击、隐藏祖先过滤、贴身双面代理检测；不修改活跃材质。
- 独立 `melee-strike.js` 管理开始、窗口、结束与取消，带单次挥砍身份集合。**本批仍保留原来最多一次接触/一个目标的上限**，没有顺手加入群体伤害。墙面或无敌核心的零伤害接触也会结束本次攻击。
- 切枪和重置取消待命攻击；暂停冻结动作，恢复后继续。完整挥空仅在窗口结束结算一次，不按采样帧重复记录射击统计、声音或伤害。
- 使用前后剩余时间的区间交集判断，覆盖 120ms 步长及单步跨过整个窗口的情况。没有改动原渲染循环的 50ms 时间上限，也没有插值重建历史敌人位置。
