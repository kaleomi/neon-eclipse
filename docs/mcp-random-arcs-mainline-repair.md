# 随机地面高压与高架检修主线

## 本轮需求与选择

用户指出原高架平台没有任务，选择将高架和运输区改为主线必经。此前原型只用于测试高度碰撞和运输承载；本轮补齐实际目标与推进条件。

## 随机高压

- 北部地面设置 8 个 4×4 米候选放电区，每轮随机选 2 个，不再固定两条长带。
- 每 6 秒一轮：安全 3 秒、黄色预警 1.5 秒、红色放电 1.5 秒。每轮开始选区，预警和放电期间不改变位置；相邻轮次不会完全重复同一组选区。
- 只有被选中的两区会高亮预警并造成伤害，其他区域保持暗色。暂停冻结计时和选区；禁用与重试从安全期重置。
- 每次仍为 8 点伤害，伤害间隔 0.6 秒，跳跃脚部高度达到 0.35 米可避开地面伤害。
- 随机是安全候选区内的随机组合，不是在整张地图随意生成。候选区不覆盖北部两侧外缘绕行空间，上传交互附近保留空地。
- 保留既有规则：Boss 存活时关闭地面高压，避免与交叉电弧叠加；高压在天线控制阶段和 Boss 击破后的上传阶段启用。核心血量仍为 1920。

## 高架主线流程

第三章的第三个阶段改为“高架检修后接管天线”，仍保持五阶段编号：

1. 完成双中继后清理当前守卫。
2. 沿东侧楼梯到高架登车口，或从地面停靠位置登上升降车；乘车到远端泊位。
3. 到远端平台实际新增的供电检修终端，面向终端按住 E 3 秒修复。
4. 目标切换到西北天线控制柜，返回后按住 E 接管，才能进入 Boss 上传阶段。

检修终端位于约 `(32.5, 17)`、脚部高度 3 米。屏幕朝向车台来向，并加入正确高度的实体碰撞和任务目标。未完成乘车时任务标记先指向登车处；完成乘车后指向远端终端。

推进条件同时验证真实运输行程与玩家站立高度：从车台随行向远端累计至少 8 米并到达远端，才记为完成乘车。只跳到远端平台、只推进车台时钟或站在平台下面操作，都不能直接完成检修。普通清敌、站稳、视线与按住 E 的交互规则保留。

## 存档兼容

不插入第六个阶段，不更改原存档键。检修与控制柜作为原第三阶段的两个连续目标。

- 已经进入上传 / Boss 或撤离阶段的旧存档直接继续，不强制回退补做检修。
- 仍在天线控制阶段的旧存档从新检修目标开始。
- 运输记录增加可选布尔字段 `transportTrip`，与现有 `transportTime` 一同恢复；旧数据无此字段按尚未完成乘车处理。
- 仍采用阶段入口检查点，不增加实时自动存档；阶段内死亡 / 刷新可能需要重新完成乘车和检修，不能把本轮改动理解为每个小目标都会自动保存。

## 验证

远端 `npm test` 全部通过，编辑器诊断 0 错误、0 警告。新增 `test-random-repair.mjs`，覆盖随机不重复选区、同轮锁定、预警 / 伤害 / 冷却 / 暂停 / 禁用、安全绕行、运输要求、高度限制、检修顺序、五阶段兼容和乘车状态恢复。

隔离沙箱中的 Chromium 受控回归验证：

- 没有乘车不能操作远端终端。
- 实际乘车到达 z=16、高度 3 米，检查点恢复仍保留乘车资格。
- 在真实碰撞场景中从车台下到平台，面向终端按住 E 完成检修，目标切换到天线控制柜，再完成控制柜进入上传阶段。
- 高压预警与放电使用同一组选区，下一轮换区。
- 既有 Boss、动作、运输、统计和雷达回归仍通过，页面异常为 0。

受控测试包含清敌、位置安排和时间推进，不等同于完整人工战斗通关或实机帧率评估。

## 后续开发方向

1. 主线任务反馈：补检修成功的供电动画、场景灯光变化、简短无线电反馈，让玩家直观看到修复作用。
2. 试玩新流程：评估乘车等待时长、检修区路线可读性与死亡重试成本；根据反馈决定是否增加阶段内检查点。
3. 多守卫楼梯让行、运输呼叫按钮、完整护栏，以及是否允许敌人登车。
4. 真正移动列车：车厢承载、安全车门、站台连接和暂停 / 存档恢复。
5. 利用 Boss 战斗记录评估 1920 血量下的补给和暴露轮数，完善音效、击败演出与性能。
