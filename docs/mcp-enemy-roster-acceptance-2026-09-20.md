## 完成数量

**当前项目敌方清单：24 类；已建模并接入 24 类；清单内未建模 0 类。**

- 普通、精英及机械敌人：15 类。
- Boss：9 类。其中 WARDEN 使用通用敌人入口，另外 8 个使用各关卡的独立世界控制器。

- 范围为现有敌方角色/机械单位/Boss，不包括场景、枪械物件、玩家第一人称手臂或未来新增角色。

此前对话逐个展示了 6 名角色。本次重新连接工作区时，护盾兵及后续批量角色、Boss、接入代码已经存在。因此本轮承接已有成果，完成全面核查、问题修正、格式验证、统一预览和完整打包；不把预先存在的模型误报为本轮重新制作。

这是与此前角色系列一致的硬表面/刚性节点游戏样板，不是高写实人体、真人蒙皮、动作捕捉或最终影视资产。

## 本轮修正

1. **移动端模型库溢出**：修正 `enemy-roster-complete.html` 的网格最小宽度约束，让窄屏模型列表在自身区域内横向滚动，而不是撑宽整页；没有用隐藏整页溢出来掩盖问题。
2. **极地 Boss 测试预期**：原批量浏览器测试把所有非暴露期 Boss 都断言为零伤害。`GLACIER_ARMOR` 原值为 0.15，5 点测试伤害应结算 0.75。现在测试从 `glacier-rules.js` 导入原常量，分别验证其护甲和核心倍率；没有改游戏伤害、生命或阶段规则。
3. **关卡截图夹具**：初始化已存在的第一人称武器姿态，修正冻结测试循环导致的视野遮挡；没有为拍照改模型、场景或战斗。补正后 Boss 浏览器入口再次通过，最终极地机甲画面已检视。
4. **旧角色反弹命中兼容核实**：当前工作区已有 `characters/hit-proxies.js` 的材质隐藏方案，保持逻辑 Mesh 可见而不绘制旧盒子。本轮用真实橙色反弹弹路径覆盖全部 16 个通用敌人类型并通过，之前记录的兼容风险在当前版本的这一覆盖范围内已完成验证。

本轮未重做/覆盖模型几何，未修改 Boss 规则、AI、存档和关卡编队；没有执行提交、推送或正式发布。新增的 `.tools/pack-roster-acceptance.mjs` 只收集已经存在的模型及来源文件，归档写入独立的 `.tools/qa-roster-acceptance/`。

## 查看与复现

- 项目三维展厅：`enemy-roster-complete.html`。
- 下载包内 `全敌人建模总览.html` 是自包含图鉴，可直接打开；缩略图均来自项目的真实 GLB 渲染。
- 下载包内运行 `node serve.mjs`，再在同一台机器浏览器打开 `http://localhost:5176`，可旋转、切换角色/动作、线框和下载 GLB；所需 Three.js 运行文件和许可证已附带。
- `models/`：24 个 GLB、各自清单及总清单；`characters/` 和 `scripts/`：模型源代码和构建脚本；`verification/`：机器可读证据。
- 下载包是**模型资产与展厅包，不是整个游戏工程**。游戏里的接入已在原项目保留，未将玩家数据、私密配置或整个项目依赖打入资产包。

项目复验命令：

```bash
node test-enemy-roster.mjs
node test-enemy-roster-world.mjs
node scripts/run-tests.mjs --layer browser --filter enemy-roster --jobs 1
```

原项目证据目录为 `.tools/qa-enemy-roster/`；本轮格式验证与交付记录存入 `.tools/qa-roster-acceptance/`。模型库、24 个模型渲染总览及代表性关卡截图已检视。

## 不在“剩余 0”的含义内

“0”表示当前声明的敌方角色名单没有缺模型，不表示整款游戏已经通过全部发布验收。真实目标显卡、多敌同屏帧耗、LOD、长时间 GPU 内存稳定性、全部武器和全部自然流程仍需专项验证。结构预算和软件 WebGL 截图不能替代这些结果。
