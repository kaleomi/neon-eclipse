## 发现与建议

### F01 — 直升机机炮输入测试时序脆弱（测试可靠性，非已确认模型缺陷）

原测试固定按住左键 500ms 后松开，随后在原 5 秒内等待 shots 增加且 ammo 下降，未满足。诊断副本把输入改为持续原生按压直到同一个 5 秒条件满足，然后 finally 松开，没有改条件或游戏。该副本越过了机炮/火箭步骤。

结论：有输入采样/调度脆弱性迹象，尚无足够证据断言唯一根因。建议在冻结版本上采用事件完成条件而非短固定脉冲，原失败保留。

### F02 — 直升机新增物资链待冻结后复验（阻断该流程的全绿结论）

诊断副本在 `loss starts the respawn timer` 断言失败：检查时 `data-sling-run-respawn` 没有正值。现有测试同时在接入物资链/医疗救援扩展，已超出最初单纯模型/吊运外观的范围。

本轮期间入口发生并行变化：

- 前：`vehicle-app.js` → `60e55ebe389d670aaf9667ebc75206663c25a3e58cc95d320c8ee6b258ba20e0`
- 后：`vehicle-app.js` → `25599871c2d2d5446a5e8beaf9829a13e667cb2e18e507fa3abdbcbcb8b21e5c`

建议先冻结入口、`helicopter-sling.js`、相关测试与救援依赖的版本，再抓取释放前后 cargo.resting / lastEvent / run.respawn 的逐帧状态，定位事件与 HUD 发布顺序。不要以拉长重生时间、删除断言或回滚并行代码来“变绿”。本轮没有修改这些文件。

### F03 — 固定翼 HUD 层叠（截图观察，需布局复核）

在本轮 960×640 固定翼飞行截图中，右侧飞行仪表与武器信息/说明文字发生重叠显示，可读性下降。已有“无横向溢出”断言不等于卡片没有互相覆盖。

建议增加飞行状态下的面板相交/可读性检查，按现有 HUD 容器重新排布。这是 UI 整合问题，不是 GLB 格式或骨骼问题；本轮未改布局。

### 人工验收边界

抽查了爆炸桶+武器、EMP+刀刃、暗场武器、换弹、飞行与吊运实图。未在这些样图中发现整个模型消失、明显丢材质或新分离部件；但暗场可读性、ADS 舒适度、天气条与刀尖视线关系仍需真人目标设备复核，不据自动化指标代签。
