日期：2026-09-20（Europe/Paris）

## 1. 范围与实施边界

用户选择「全套 UI」和「简洁科幻」，重点是不再把画面、声音、操作等设置挤在同一个长页面。

接入时，工作树已经包含 `ui-navigation.js`、`ui-panels.js`、`ui-shell.js`、`ui-clean.css` 及其入口整合和浏览器测试。本轮先审查并复用该草稿，再补齐视觉缺陷和验证；没有叠加第二套菜单，没有重置或回滚已有并行工作。

现有控件采用移动原节点的方式组织，保留监听器、设置模型和保存规则，不复制一套脱离真实状态的表单。测试使用隔离的浏览器上下文与测试服务器，不读取、清空或迁移玩家浏览器中的存档。

## 2. 界面组织

| 区域 | 当前结构 |
| --- | --- |
| 主菜单 | 总览、章节行动、装备管理、设置、战斗记录、成就与收藏分开；其他行动保留独立入口。 |

| 装备 | 携带配置、改装工坊、使用说明分开。工坊一次展示一把武器，保留原下次章首草稿、解锁和重开确认。 |
| 战斗 HUD | 左侧当前任务与收藏进度，右侧三把实际携带的中文武器及总弹药百分比，底部生命与当前弹匣；临时提示集中排列。 |

| 海陆空菜单 | 开始／继续、先遣队战役、独立任务、设置与说明、成绩与备份分开；独立任务进一步按任务选择。 |

## 3. 本轮发现并补齐的问题

### 3.1 精简 HUD 的旧固定高度

旧皮肤在精简模式把未选中卡片固定为 32px，光环精准步枪的特殊选择器还会压到 29px。原有测试只检查三张卡片存在，未发现名称和弹药行越界。

新增 `test-ui-clean-layout-browser.mjs`，先复现失败：未选中的幽灵消音手枪内容超出自己的卡片。随后在 `ui-clean.css` 中明确让装备卡片按内容自适应高度，保留每把武器下方的弹药条；近战继续显示真实的无限弹药语义，不伪造有限百分比。

### 3.2 结算主操作被挤出视口

旧预览图仍跨越两个网格行，加上旧 ID 选择器留下的超大标题，导致下一关按钮落到被页脚遮挡的位置。

现在预览、内容和操作区使用明确的网格行；主要操作停留在可见的下方区域，文字区可以单独滚动。存档警告出现时也为操作区预留空间。同时压缩战报段落的默认外边距，数值单位保持同行。

### 3.3 分类选中状态不清晰

提升共享分类选中样式的选择器优先级，防止载具页面原有按钮样式覆盖当前分类背景。保留悬停、键盘焦点和 ARIA 状态。

### 3.4 收藏进度覆盖任务卡

`star-world.js` 的收藏标记原本使用固定位置，恰好压在新任务卡标题区。`ui-shell.js` 现在将原节点收进任务卡下方；其统计、显隐和收藏状态仍由原系统控制，不改变收藏判定或进度。

### 3.5 装备说明与按钮文案

`loadout-world.js` 本轮仅调整两处界面文案：携带说明改为包含可选近战装备的准确表述，按钮改为「应用携带配置」。没有修改换装距离、视线、楼层、忙碌限制、库存或终端逻辑。

## 5. 验收入口

现有 `server.cjs` 已启动，继续使用原来的浏览器、主机名与端口，以保持存档来源不变：

- 主游戏：`http://localhost:5173/index.html`
- 海陆空：`http://localhost:5173/vehicle.html`
- 行动中枢：`http://localhost:5173/p4-hub.html`
- 行动档案：`http://localhost:5173/operations-archive.html`
- 旋翼试飞：`http://localhost:5173/helicopter.html`

建议按 `Ctrl+F5` 后检查：

1. 打开设置，分别切换画面和声音，确认另一分类的控件不再混在当前页。
2. 检查操作、界面与语言等分类，修改偏好后刷新，确认原有持久化仍有效。
3. 打开装备管理，分别查看携带、工坊与说明；工坊切换武器不会直接改动当前携带。无需为了验收点击重开按钮。
4. 游戏中检查滚轮切换、三把武器、各自下方的弹药条及任务卡内的收藏进度。
5. 暂停后进入设置，第一次 Esc 返回暂停页，第二次 Esc 继续；结算主要操作不需要滚动寻找。

无新增部署依赖；未修改存档格式、枪械标识、弹药规则、掉落概率或终端交互权限。
