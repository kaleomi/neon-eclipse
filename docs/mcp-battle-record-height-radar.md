# Boss 战斗记录与高低层雷达

## 本轮交付

### Boss 战斗记录

第三章枢纽监察者激活时开始记录，暂停不累计时间。暂停菜单可看当前记录，胜负结算显示本次结果。

记录内容：战斗用时、核心暴露轮数、核心 / 节点有效伤害、步枪 / 霰弹枪 / 手枪开火数量、近战起手次数、Boss 电弧实际扣血，以及结束时生命和各武器剩余总弹药。

- 开火数统计 Boss 存活期间的全部射击，包括守卫、节点和未命中；不是只统计命中 Boss 的弹药。
- 霰弹一次开火记一发，不按弹丸数量累计。
- 电弧扣血按实际生命损失统计，不包含守卫及环境伤害。
- Boss 被击破时冻结成功记录；之后被守卫击倒不会把这次 Boss 击破改记为失败。
- 暂停不清空；重试 / 新行动重置。本版只有当前页面、当前尝试的内存记录，不保留多次历史，不写入旧检查点，也不发送到外部服务。
- 近战记录起手次数，即使中途切枪取消仍属于一次起手，不等于命中次数。

Boss 核心血量保持 1920，二阶段仍在 960 触发，节点和攻击参数不变。本轮提供试玩记录工具，没有根据模拟数据擅自调整平衡。

### 高低层雷达

使用相对脚部高度比较敌人与玩家：高于 0.8 米显示上三角，低于 0.8 米显示下三角，其余显示圆点。图例同时显示高处 / 同层 / 低处守卫数量，不只依靠颜色区分。正确从玩家相机高度扣除 1.7 米眼高，避免同地面敌人被误判为楼下。

雷达保留原有视窗限制：宽度小于 1100 或高度小于 750 时隐藏；不是新增敌人透视或箭头指引。它显示相对高度，不代表已经识别了整张地图的楼层编号。

## 验证

- 远端 `npm test` 全部通过；新增 `test-battle-record.mjs`。
- 测试覆盖时间、暂停、弹药计数、核心暴露轮数、伤害分类、结束记录不被覆写、快照隔离、重试，以及雷达高度与绘制形状。
- 隔离沙箱加载远端源码，用 Chromium 受控回归验证实际霰弹计数、暂停记录、失败结算、重试清空、真实延迟近战击杀冻结成功结果、后续失败不覆盖结果，以及雷达图例人数。
- 1920 HP 血条 / 二阶段、上下楼、车台承载与恢复、冲刺、换弹等既有回归仍通过，页面异常为 0。

测试用了受控清敌、伤害与时间推进，不等同于新版完整人工战斗通关或用户机器性能评估。

## 使用

Ctrl+F5 刷新第三章，进入上传阶段。战斗中按 Esc 查看本次记录；失败或完成行动后也可查看。可把记录截图反馈用于后续平衡。

主要文件：`boss-battle-record.js`、`boss-record-ui.js`、`radar-height.js`、`app.js`、`overseer-world.js`、`radar.js`、`test-battle-record.mjs`。

5. Boss 命中音效、节点爆裂、核心过载演出及实机帧时间优化。
