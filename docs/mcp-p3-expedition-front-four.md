## 1. 交付结论与范围

把已有的四个任务串成可保存关间进度的独立流程：

1. 荒原车队护送（越野车 / 车顶机枪）。
2. 南湾突围（游艇海战）。
3. 回声航线（固定翼低空侦察 / 返航上传）。
4. 海空接力（陆海空换乘 / 侦察 / 最终交接）。

这是**复用现有任务的串联与成绩批次**，不是新增四张地图，也不是完整八关先遣队战役已经完成。第 5–8 关、完整先遣队称号、直升机等新载具与大地图流式仍未交付。

## 2. 如何使用

入口：`vehicle.html` 的初始菜单或暂停菜单 → **先遣队 · 前四关**。

- 选择新战役前两关的难度，点击“新建前四关战役”，再点击确认；新建会替换关间进度，但保留历史成绩。
- 第 1/2 关使用该战役锁定的简单 / 普通 / 困难档，不改变原单项任务的难度偏好。
- 第 3/4 关沿用现有固定规则，成绩明确标记“固定规则”，不伪造三档难度。
- 本关完整通关后，**进度和成绩在同一个事务提交成功才推进**。从先遣队面板确认开始下一关，不自动跳过任何任务。
- 暂停不会结束当前关；失败可以从同一关关首重试。刷新后已完成关卡保留，未完成关卡从关首重来。
- 可以退出本关回自由试驾，已保存的关间进度与成绩保留。
- 保存失败会保留本页待保存结果并显示“重试未保存结果”。多页面冲突不会自动覆盖，需明确选择读取最新档案；放弃待保存结果会先确认。

菜单采用独立样式，不修改既有驾驶 HUD 布局；游戏中在原目标区的小标题标记先遣队当前关及实际难度口径。

## 3. 成绩与检查点边界

| 场景 | 先遣队进度 / 成绩 | 既有单项行为 |
| --- | --- | --- |
| 从先遣队面板开始并完整通过当前关 | 原子保存当前关成绩并解锁下一关 | 侦察不重复写入原单项飞行成绩 |
| 失败、提前退出、调度、切换任务 | 不计成绩、不推进；保留上一个关间节点 | 原任务重置规则保留 |
| 从原南湾 / 联合安全检查点恢复 | 退出先遣队本关所有权，不推进、不计分 | 保留原模板恢复和“检查点继续”标签 |
| 从原按钮开始单项任务 | 不推进、不回填先遣队记录 | 原飞行成绩、海战、联合任务行为保留 |
| 同一次完成回调重复触发 | 不重复提交；仍标记为先遣队来源，避免落入单项飞行成绩 | 不产生额外记录 |
| 新建另一轮先遣队 | 仅替换当前关间进度，保留历史合格成绩 | 不改旧任务存档 |

成绩按任务、规则版本和实际难度分组，显示完成次数与最好用时。只记录每关从头开始的完整一命结果；不提供全战役一命排行榜，不把跨关刷新伪装成全战役一命。

“status=won”本身不足以计分：还要检查护送到站 / 三波清除 / 载具存活、海战三门 / 撤离 / 解除追踪、侦察完整扫描 / 返航 / 停稳 / 上传、联合任务九阶段完整交接等对应证据。结果同时绑定本轮实际任务对象，不能用其他模式或旧任务的结果推进。

## 4. 存储与故障保护

- 独立 IndexedDB：`neon-eclipse.expedition.v1`。档案规则为 `front4-v1`，包含当前战役、锁定难度、按顺序完成的记录 ID 和成绩历史。
- 复用已有 `createCheckpointStore` 的单行比较并交换事务；未修改其实现或旧数据库名称。
- 进度与成绩在同一事务写入，提交前不会乐观显示“已保存”或解锁下一关。
- 稳定操作 ID 支持确认丢失后的幂等重试；并发版本冲突拒绝覆盖。
- 损坏、未知版本、权限拒绝、配额不足均显示错误并保留原数据；不自动重建数据库或清空存储。
- 成绩上限 1000 条，不自动淘汰旧成绩；达到上限后阻止开始新的计分关卡，后续需另做明确的档案管理。
- 当前不读写 FPS 战役 / 星星 / 成就、单项飞行成绩或原检查点中的历史数据。
- **先遣队新档案暂未接入 SaveHub 导出 / 恢复**。它是本地浏览器、同站点来源下的数据；强制关闭可能丢失尚未提交的结果，更换来源或清除浏览器数据不能视为已有备份。

为避免等待检查点存储的异步启动覆盖用户后来选择的任务，载具入口增加 `missionIntent` 校验：新的回收 / 调度 / 任务选择会使旧启动请求失效。
