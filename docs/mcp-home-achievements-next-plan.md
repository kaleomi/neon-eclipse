## 二、当前阶段判断

六章内容、连续战役、检查点、隐藏收集、单章成就、菜单和续关流程已经接入。当前更值得投入的是：**让战斗更好玩、让挑战反馈更清楚、让完整流程更稳定**。

不建议下一轮继续扩张首页，也不建议在缺少试玩数据时直接开第七章。新增功能优先进入现有二级页面。

下面均为后续建议，除第一节明确列出的内容外，本轮没有擅自实施。

## 三、分轮开发路线

| 顺序 | 主题 | 主要交付 | 验收重点 |
| --- | --- | --- | --- |
| M1 | 近战手感与挑战可玩性 | 近战判定/动画一致性、Boss 近战窗口检查、对应回归用例 | 命中反馈可信，不隔墙、不重复伤害；纯刀规则不回归 |
| M2 | 成就反馈与奖励展示 | 当前章筛选、未解锁/已解锁筛选、挑战进度、徽章/称号与短提示 | 真实状态驱动；读档、死亡、重试不会错误授予成就 |
| M3 | 六章实战节奏 | 港口波次/补给、楼梯和窄桥交战、主线反馈与重试成本调整 | 用真实承伤/耗弹/死亡位置等数据指导调整，不只堆血量 |
| M4 | 性能与存档保障 | 目标设备分档测试、针对性优化、本地存档备份/恢复、运行说明 | 帧时间改善可复测；备份校验与恢复不会破坏旧记录 |
| M5 | 差异化新内容 | 先做现有关卡事件或精英的小型可玩片段，再决定整章扩展 | 新机制有辨识度，包含成功、失败、返回和存档完整流程 |

### M1｜优先改善近战，而不是先改数值

现有刀具已具备挥砍动作和接触时机，但命中仍复用单条准星射线。先验证体感问题，不将这种实现直接认定为已经复现的 Bug。

建议工作：

1. 建立贴身、目标边缘、掩体旁、挥砍中切枪、暂停恢复和较大帧间隔的测试场景。
2. 对照动画与命中反馈，确认哪些情况会出现“看似砍到却未命中”。
3. 如确认需要更宽容判定，再实现有限角度的短弧采样或体积扫掠；保持距离限制、墙体遮挡和单次挥砍伤害去重。
4. 检查 Warden、枢纽监察者节点/核心、港口精英暴露窗口的实际近战可操作性。
5. 做真人无辅助试玩，记录问题；不要用受控结算代替纯刀难度验证。

验收：动作与反馈一致，不穿墙砍人、不重复计数；原枪械逻辑、成就资格和存档测试通过。Boss 血量与既有星星难度不在这一轮无依据调整。

相关模块：`combat.js`、`action-poses.js`、`app.js`、`overseer-rules.js`、`enemy-rules.js`。

### M2｜让成就从“能看见”变成“值得追求”

已有成就条件和基础资格说明，本轮也已补上独立入口。下一步不是重复创建成就系统，而是补足展示与反馈：

- 按当前章节、全部章节、已解锁/未解锁筛选。
- 在成就页或暂停页显示四种武器分别击破的进度，以及港口暴露核心击破的 `0/3` 进度。
- 对纯刀、无伤、一命挑战区分“本轮仍有效”“本轮失效原因”“历史已获得”，避免三种信息混在一起。
- 增加可关闭的短解锁提示、专属徽章或称号；不默认附带伤害加成，避免破坏现有平衡。
- 统一挑战重开确认，离开页面时取消临时确认状态，减少误重开。

验收：所有进度来自实际开火、承伤和击破事件；加载检查点、死亡、阶段训练与损坏/受限存储不会错误解锁或覆盖已有荣誉。

相关模块：`chapter-achievements.js`、`achievement-ui.js`、`menu-ui.js`、`app.js`。

### M3｜用试玩数据调整关卡节奏

优先检查：

- 风暴港口：24 秒信标防守的三批增援、最后一批压力、三名精英的反击窗口和弹药余量。
- 中枢塔：楼层方向辨识、楼梯拥堵和上下层交火。
- 货运列车：车厢视线、窄桥拥堵、车顶风险与跌落后的返回体验。
- 六章共性：交互完成后是否有足够清晰的灯光、音效或简短提示；死亡后需要重复的操作是否过长。

先利用已有本页战斗报告，逐章导出承伤、耗弹、用时、死亡位置和窗口利用记录。当前报告不跨刷新/跨页保存，不能把它当作已有的完整战役汇总。确需跨章对比时，再增加可选的本地汇总，不默认上传。

验收：调整前后用相同路线与目标记录比较；主线可完成、失败能返回，不擅自恢复第三章已经取消的强制运输主线。

### M4｜稳定性、性能和存档安全

这部分的最小保护措施应贯穿每轮，而不是全部拖到最后：

- 下一次较大玩法修改前，核对并建立可回滚版本或备份。此前未检测到 Git，实施时应重新确认，而不是假设已经有版本历史。
- 把菜单、章节切换、检查点、星星、挑战资格和保存失败的浏览器用例整理成项目内可重复执行的入口。
- 在目标 Windows 设备上先确认分辨率与帧率目标，再逐章采样三档画质的帧时间、低帧表现及内存趋势。
- 根据瓶颈优化粒子 CPU 更新、阴影范围、绘制批次、导航或 UI 更新频率，不盲目叠加特效。
- 增加可选本地存档备份与恢复。导入前校验结构/版本，先备份现有记录，并确认覆盖范围。
- 补齐运行说明、操作说明、已知限制与交付检查清单。

验收：优化结果可在同一设备/场景复测；存储失败不假报成功，损坏文件不直接覆盖现有记录；旧版本进度仍能按已有规则迁移。

### M5｜新内容先做小片段，再开整章

优先考虑能利用现有模块、又能带来新体验的内容，例如列车隧道/限高预警事件、中枢塔专属精英或更有反馈的环境交互。

如果确定要第七章，先交付一段小型可玩片段：一个明确的新机制、一种具有区别的敌人组合，以及完整的进入、完成、失败返回和存档流程。通过试玩后再扩展整章，避免重复“清敌 → 按 E → 防守 → 撤离”。

联机、云存档、可驾驶载具属于独立大功能，不混入一次菜单或近战迭代。

## 四、建议下一轮直接执行的任务单

**建议主题：近战手感专项，并补最必要的挑战进度反馈。**

1. 固定当前可回退版本，建立近战边缘命中/遮挡/单次伤害的复现场景。
2. 验证并改进近战判定与挥砍反馈；不顺手重写所有战斗系统。
3. 在成就页补充四武器击破和港口破核进度，不再往首页堆信息。
4. 回归纯刀资格、死亡重试、读档、Boss 节点和现有全部测试。
5. 交付可试玩版本及验证记录；收集真实手感反馈后，决定是否继续调整遭遇与数值。

徽章美术、完整筛选器和新关卡可以放到之后的轮次，控制这次迭代范围。
