# 侦察方向与扫描反馈｜源码交付和后续路线

## 本轮完成

延续上一轮三维圆柱高度带，不改变扫描判定、物理参数或成绩规则版本，补齐“进入圆柱后为什么仍不能扫描”的操作反馈。

1. **空中方向箭头**：当前圆柱内有三组立体箭头，朝向与真实飞行航向约定一致；不是增加新的碰撞障碍。
2. **六项条件提示**：范围/起飞、高度、航向、速度、姿态，以及是否满足实际扫描/视线检查。需要调整时直接显示向左/向右转、加速/减速、放平机翼或减小升降率。
3. **场景目标下的进度条**：未满足条件时显示“等待条件”；满足后提示按住 F；扫描时显示当前累计秒数和进度，切换目标归零。
4. **就绪颜色反馈**：只有任务实际判定为可扫描或正在扫描，圆柱和空中箭头才转为青绿色。单纯达到高度不等于全部条件合格。
5. **减少重复信息**：扫描阶段的进度移到场景目标处；保留返航地面上传面板、飞行仪表和原有告警。调整中等宽度及窄屏布局。

条件面板的飞行数据来自当前飞机状态，最终扫描提示和就绪颜色使用任务判定结果；没有另写一套近似遮挡判定来宣称“可以扫描”。实际扫描仍要求连续满足条件并按住 F。

## 下一步开发方向——尚未实现

### 优先：一条连续的陆海空短任务

先复用现有试验区和安全上下车机制，计划路线：

**地面接取任务并抵达码头 → 驾船完成交付并返港 → 经陆路到机场换机 → 空中侦察 → 返航交接。**

先做一条有限路线，不扩开放世界或第七章。重点不是增加菜单入口，而是让上一阶段完成后解锁下一阶段，所有阶段目标都保留场景内引导。

验收重点：安全靠泊/停车后换乘、阶段推进不可跳过、模式切换时清理输入与危险对象、失败/重开不重复结算。联合任务与现有单项任务的成绩资格必须区分。

### 随后：安全节点检查点

在安全交接节点恢复任务状态，不保存危险的半空瞬间；明确检查点恢复与完整挑战成绩的区别，避免借恢复刷成绩。
