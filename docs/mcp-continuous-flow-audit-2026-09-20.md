# 九章与载具连续流程：存档衔接自动化验收

日期：2026-09-20；项目：`game/`。

## 本批范围

新增 `test-journey-continuity-browser.mjs`，使用实际应用页面、菜单、场景构建、会话流程和存档模块，补上同一份九章战役存档的连续衔接测试。

测试通过浏览器响应注入专用钩子，冻结自动战斗更新，并受控设置检查点、触发失败及结算；游戏源码不包含这些钩子。它验证的是入口、恢复、保存和导航合同，不是九章自然战斗通关。

所有浏览器使用独立临时上下文和测试服务端口；不读取或清空玩家实际浏览器存档。测试结束后关闭浏览器和服务端。

## 九章检查矩阵

顺序：反应堆 → 运输站 → 天穹通讯枢纽 → 中枢塔 → 货运列车 → 风暴港口 → 轨道电梯 → 数据中心 → 极地。

每章检查：

1. 从真实菜单启动，实际地图与战役章节序号一致，WebGL 画布存在。
2. 执行一次实际游戏更新，再由键盘暂停、菜单继续。
3. 保存受控检查点，包含非默认生命值及已消耗的弹匣弹药。
4. 受控失败后，实际重试按钮恢复检查点；失败不增加章节结果。
5. 重新加载页面，通过主菜单继续，核对阶段、生命、弹匣、备用弹药、选中武器、时间、击杀及战备／类型弹药字段。
6. 受控结算后使用实际“进入下一关”按钮，保持一份连续战役，而非为每章预先写入完成档。
7. 单章存档槽和额外哨兵键保持不变；第九章结束后结果数为 9、状态为 complete、检查点为空，主按钮返回主页。

额外模拟：第一章结果写入失败时保留内存中的待保存结果与旧存档，重复点击不导航也不改持久化字节；第二章下一关入口写入失败时仍保留 between 状态，解除故障后才推进。

## 载具与持久化检查

使用既有专项测试，分别核对：

- 八任务载具战役：实际菜单确认、任务入口、难度锁定、失败／无效结算拒绝、重复回调、单任务模式脱离、检查点恢复、恢复成绩与完整起点成绩分流、完成后重载和窄屏布局。胜负及部分位置使用受控夹具，不代表实际驾驶完成八任务。
- 原生 IndexedDB：多页面版本冲突拒绝陈旧写入，配额失败不提前推进，事务中止回滚，已提交但未收到确认的重试去重。
- 实际备份组件：旧版只读导出、文件下载、预览／取消不写入、替换与撤销、重载、无效／超大文件拒绝、跨系统数据隔离，以及未知未来数据保留。
- 纯规则与内存故障注入：九章存档顺序、会话恢复、旧版迁移、备份写入失败、部分恢复及重试。

- 本批没有证明所有地图目标触发、Boss 战、撤离条件和驾驶路线都能自然完成；胜负由测试钩子触发，不能用这些结果声称“九章已自然通关”。
