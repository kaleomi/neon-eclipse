# 直升机吊运玩法方案（待选，2026-09-21）

b18 交付了吊挂的物理与判定（`helicopter-sling.js` / `helicopter-sling-world.js`），但"吊运任务化 / 计分 / 对飞行动力学反馈 / 音效"留空。本文给出三个可独立落地的方案供选择；只写方案，未动代码。三者共用现有 `createSling` 事件（hooked / delivered / dropped / broken）与 `SLING_ZONES`，实现代价按 b18 同等验收（rules 测试 + 直升机场地链）估算。

## 方案 A：补给链（最小）
- 玩法：岸边停机坪出现 3 箱物资，依次吊到车库物资区 / 灯塔岛平台 / 新增的哨站屋顶；每箱送达刷新下一箱与目标区；三箱送齐解锁先遣队第 5 关的"补给完成"奖励（弹药箱 + 机炮冷却缩短）。
- 张力来源：只有摔坏惩罚（重新生成 8 s 等待）；无计时。适合当作教学关。
- 改动：`helicopter-sling.js` 增 `createSlingRun(zones)` 状态机（pure），`vehicle-app.js` 接 delivered → 下一箱；`#vw-hint` 显示 x/3；`SLING_ZONES` 加 1 个点。
- 验收：`test-helicopter-sling.mjs` 加状态机分支；场地链加一段送达两箱。
- 代价：约 1 个批次。

## 方案 B：限时急救吊运（中）
- 玩法：灯塔岛上出现伤员箱（倒计时 90 s），须从岛吊回岸边医疗区。箱内"生命值"随摆动幅度衰减（弹簧摆角 > 25° 每秒扣血），高空摔坏直接失败。完成按剩余时间 + 剩余生命给评级 S/A/B。
- 张力来源：稳飞与速度的取舍，直接利用已有的弹簧滞后摆动数据（`sling.swing`）。
- 改动：在 A 的状态机上加 timer + cargoHealth；`vehicle-touch.js` 无需改；HUD 加倒计时与箱体血条；箱体损坏视觉复用 b18 深色材质。
- 验收：rules 覆盖摆角扣血阈值、超时失败、评级边界；场地链验证一次 B 级完成。
- 代价：约 1.5 个批次；评级数据可接入 `campaign` 存档（可选）。

## 方案 C：吊运 + 飞行动力学反馈（大）
- 玩法：在 A 或 B 基础上，箱体质量影响直升机：悬停功率上限下降 15%，箱体摆动给机身施加水平扰动力（`sling.swing` 投影到直升机速度），重箱（新增 2 t 变体）必须先加速再爬升。
- 张力来源：真正的"吊重感"，是 b18 明确列出的未做项。
- 改动：`helicopter-physics`（现 `vehicle-app.js` 中直升机步进）接入 `sling.load()` 返回的质量与摆动向量；需要重新校准现有直升机链的悬停/降落断言。
- 风险：会改动现有直升机手感，`test-helicopter-field-browser.mjs` 里的悬停高度、降落速度阈值大概率要重采基线；触屏操控在扰动下的可用性未知。
- 代价：约 2–3 个批次，且建议先做 A 再叠加。

## 建议
先 A（一个批次、零手感风险、把"任务化"和"计分"两个空位补上），再按体验反馈决定是否叠 B 的计时/血量或 C 的动力学。音效三案通用：hooked / delivered / broken 三个事件各接一个 `sfx-player` 事件，可在任一方案内顺带完成。
