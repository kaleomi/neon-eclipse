# P3 第六批：H-01 直升机独立原型

日期：2026-09-18。接续 `docs/mcp-p3-expedition-backup-recovery.md`，对应总体方案 §7.3 的垂直起降与简化操控。

## 1. 交付范围与入口

新增独立页面 **`helicopter.html`**。在现有游戏站点，将路径改为 `/helicopter.html` 即可打开；沿用项目 HTTP 服务与既有 Three.js 依赖，不要直接双击 HTML。

- 独立 H-01 程序化模型与 220 × 220 m 试验场，A / B 两个起降坪、维修库 / 观察塔 / 货箱障碍。
- 垂直起降、旋翼起转、自稳悬停、机身倾斜平移、偏航、制动与近地缓降。
- 四段**本页练习**：起飞 → 悬停 → 转场 → 降落；可完成后继续自由试飞。它不是先遣队前四关，也不是第 5 关。
- 跟随 / 俯视视角、航向 / 高度 / 垂直速度 / 水平速度 / RPM 仪表、目标范围和稳定计时、小地图与明确失败原因。
- 暂停、失焦 / 切后台冻结、明确确认后的复位；失败后重新试飞。
- 默认静音，可主动开启程序化旋翼声；复用既有音频总线，但音频偏好仅存在本页内存。

**不改原主菜单和 `vehicle.html` 入口，不读取、不替换先遣队 / FPS / 单项成绩 / 检查点。** 此批采用直接独立页面入口，以免干扰并行稳定性整理；没有把半成品载具塞进原四关。

## 2. 操作

| 操作 | 按键 / 入口 |
| --- | --- |
| 开始 / 继续 | 页面按钮；按钮聚焦后 Enter 或空格 |
| 上升 | Shift |
| 下降 | Ctrl 或 C；与 WASD 同时使用时推荐 **C**，避开浏览器 Ctrl 快捷键 |
| 前后倾斜 | W / S；上 / 下方向键同义 |
| 左右倾斜平移 | A / D；左 / 右方向键同义 |
| 偏航 | Q / E |
| 制动、自稳 | 空格；同时停止升降指令并减小水平速度 |
| 跟随 / 俯视 | V 或视角按钮 |
| 旋翼音 | M 或音频按钮，默认关闭 |
| 暂停 / 继续 | Esc；窗口失焦、页面隐藏会暂停，但不会自动继续 |
| 复位 | R 或“回到 A 坪”；需再次明确确认。试飞中止后主按钮可开始新一轮 |

先按 Shift 升至约 10 m，再松手等候悬停；沿目标飞向 B 坪上方约 14 m，降低水平速度后用 C 缓降。临近地面保持水平，不要一边大幅侧倾一边着陆。

窄屏布局可查看和使用界面，但**未实现触屏飞行控制**，仍需键盘。关闭 / 刷新页面会丢失本页练习状态，这是本批无持久化的明确设计。

## 3. 规则与实现边界

- 纯规则使用 **1/120 s 固定子步**；单次外部帧最多处理 0.1 s。暂停不累计补算，恢复时不会把离开页面的长间隔一次性施加到直升机。
- Shift / Ctrl / C 是简化的垂直速度指令；控制器调整集体距、补偿倾斜造成的升力损失。WASD 控制机身倾角，松开后自平衡并减速，空格增加制动。
- 默认采用辅助飞控；不是完整气动解算，不模拟涡环、尾桨扭矩、风扰、燃油、桨叶逐片碰撞或自转迫降。
- 起转有时间过程，旋翼未建立足够转速时不能立即离地。近地 4 m 内下降目标限制至 1 m/s，仍可因快速侧移或倾斜触地失败。
- 安全着陆检查下降速度、水平速度与姿态；碰撞后停止本次模拟，不自动传送回起点，不授予成功着陆。
- 碰撞采用保守机体 / 旋翼 / 尾梁包络，包含倾斜后的起落架低点；平面边界 ±110 m，安全空域 65 m **包含旋翼包络**。建筑是障碍，不提供屋顶停机功能。
- 练习必须依次满足范围、高度、稳定与落地条件，离开条件会重置当前稳定计时。结果只是本页反馈，没有最好用时、难度锁定成绩或先遣队称号。
- 场景不启用实时阴影贴图，像素比上限 1，绘制上限 30 Hz；暂停时按需重绘。它们是负载控制设置，**不是目标 Windows 设备达到稳定帧率的验收结论**。

## 4. 存储与并行改动保护

原型没有保存、导入、检查点或成绩接口；也不读取旧页面的音频偏好。

`helicopter-audio.js` 复用 `audio/audio-bus.js`，显式传入内存适配器。不能用 `null` 冒充隔离，因为现有总线的 `storage ?? globalThis.localStorage` 会回退到共享存储。此批没有修改共享音频模块。

所有新增代码 / 测试都使用 `helicopter` 专属文件名。既有 `vehicle-app.js`、旧物理、FPS、先遣队、SaveHub、菜单、依赖与服务器文件受开工 SHA 快照保护；路线图仅做 P3 范围的版本保护更新。本会话没有 Git 暂存 / 提交 / 回退，未操作另一会话的稳定性提交，不制作 EXE。

### 方法与限制

- 飞行浏览器测试使用真实键盘事件、真实 WebGL、真实本地存储哨兵，以及**受控 50 ms 浏览器时钟**。没有写入直升机位置、直接推进步骤或注入成功状态。
- 暂停断言期间推进测试时钟，验证游戏自身确实冻结；不是停止时钟后把不动误判为暂停正确。
- 并非所有测试都一次通过：首次仓库碰撞测试误把 A 坪正西航线当成仓库航线，实际正确触发边界；改为先向北进入仓库所在区域，并保留边界断言。随后发现快速缩窗时 canvas 残留旧内联宽度，修复为 CSS 管布局、Three.js 只改绘图缓冲尺寸。没有放宽飞行或碰撞断言。
- 沙箱初次浏览器启动缺少 Linux 库，已在 Arena 沙箱安装所需依赖；**用户 Windows 和项目 package.json 未安装或升级任何依赖**。沙箱使用与项目依赖匹配的 Three.js 0.186，以及 Playwright 1.58。
- 根据并行稳定性整理的低负载安排，远端只进行新增模块的单任务语法 / 规则 / 集成检查；不重跑完整默认套件、旧联合长流程或 Windows 浏览器压力测试。
- 不把规则采样频率等同于实测 FPS；不把沙箱浏览器通过等同于真人手感或目标设备性能验收。

远端轻量复跑：

```bash
node scripts/run-tests.mjs --filter helicopter --jobs 1 --verbose
```

浏览器专项另行安排，须与用户试玩和其他验证错开：

```bash
node scripts/run-tests.mjs --layer browser --filter helicopter --jobs 1 --verbose
```

浏览器需要既有 Playwright；脚本可自建、关闭其测试服务器，也可用 `HELICOPTER_TEST_URL` 指向专用测试站点。不要连接真实玩家浏览器配置，不要用清档换测试通过。
