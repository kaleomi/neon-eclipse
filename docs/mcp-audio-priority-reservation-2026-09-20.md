# 密集交火：关键音频提示容量保护

日期：2026-09-20；项目：`game/`。

## 复现与修复

旧实现中，24 个普通单次音效事件占满 SFX 播放器后，新的 `telegraph.purple` 被拒绝。修改前真实 Web Audio 受控测试得到：ordinary=24、accepted=false、active=24；记录保留在 `.tools/audio-priority-before.log` 和 `.tools/qa-audio/priority-before.json`。

采用容量预留，不抢占或提高音量：

- 每个 SFX 播放器的总上限仍是 24 个活跃单次音效事件。
- 普通事件在总活跃数达到 20 时停止进入，最后 4 个位置只供受保护提示使用。
- 关键事件可使用全部 24 个位置；全部占满时仍拒绝新事件。不承诺每个预警一定播放。
- 不截断已有声音，不排队延后补播，不修改配方、音量、音高、冷却、听觉距离或空间遮挡。

这里的声部是原播放器计数的“事件”，不等同 Web Audio 振荡器数量，也不包括独立配乐／环境循环。极端密集时，普通枪声、击中、击杀和一般 UI 音效可能更早被省略，这是为关键提示留出空间的明确取舍。

新增 `audio/sfx-priority.js`，显式保护 20 类已有事件：七色敌人预警、Boss 阶段与弱点窗口开闭、精英排气、TETHER／ABYSS／GLACIER 攻击预警、环境伤害、低血量受伤与心跳、载具失速、低温和冰裂警告。其他事件不会仅凭名字相似自动获得保护。

`audio/sfx-player.js` 仅引入该策略并调整入场容量判断。保留并行工作新增的 `preloadFiles` 及按需预载能力；不覆盖其他会话改动。未修改战斗、存档、素材文件或授权署名。

## 验证范围

新增 `test-audio-priority-browser.mjs`，在真实 Web Audio 节点与实录步枪解码上制造可重复的声部压力。它不是自然战斗录像：普通负载安排在未来时间点，以固定计数并隔离预警信号；实录负载测试仅在夹具内取消枪声冷却，生产冷却未改。

检查内容：普通事件预留阈值、全部 20 类受保护提示、实录枪声负载、四个保留位置、普通与关键事件的总上限、原冷却与距离拒绝、暂停、重置与再使用、配方数据不变。新增信号检查确认预警产生输出，并在越过负载计划开始时间后确认重置没有迟到输出。

既有音频规则、上一批状态竞争与生命周期、混音通路、实录音频及原生 FPS／载具入口分别回归；自动化通过不代表实际扬声器上的听感验收。

## 验证结果

修改后同一压力入口结果：ordinary=20、accepted=true、active=21。最终压力与信号专项 16 项通过，全部 20 类提示逐一验证；录音浏览器 23 项、33 份解码和实际极地页面通过；原生载具 5/5 通过；旧音频规则、竞争、生命周期及四组混音通路回归通过。IDE 错误／警告诊断为 0。

完整回归：`.tools/audio-priority-verified.log`，`AUDIO_PRIORITY_EXIT=0`。增强信号检查：`.tools/audio-priority-signal.log`，`AUDIO_PRIORITY_SIGNAL_EXIT=0`。最终结构化结果：`.tools/qa-audio/priority-after.json`。

|---|---|
| 自动武器持续射击＋远程敌人锁定 | 预警是否能被识别，而非只证明已创建声源 |

| 配乐探索／战斗切换、环境循环边界 | 接缝、突变、点击声、淡入淡出听感 |
