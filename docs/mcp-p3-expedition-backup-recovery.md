## 2. 如何操作

### 备份与恢复

1. 刷新载具页面，在“先遣队 · 前四关”中展开“先遣队档案 · 独立备份 / 恢复”；也可在主菜单设置的 SaveHub 中操作该独立分区。
2. 使用“导出先遣队备份”，保管下载的 `neon-expedition-*.json`。文件仅在本地处理，不上传网络。
3. 选择文件，核对当前 / 导入后摘要，再确认“替换先遣队档案”。也可以取消，预览不会写入。
4. 替换成功后，可“预览撤销上次替换”并确认；当前档案会成为新的撤销副本，可反向恢复。
5. 只保留一份撤销副本。再次进行不同内容的替换会更新它；需要更久的历史，请另存 JSON。导出的文件不嵌套撤销历史。
6. 配额或未确认提交可重试同一确认操作；如果提示预览后档案已变化，取消并重新预览，不自动覆盖。

载具页进行中的先遣队、正在保存或尚待重试的操作会锁定备份操作；先退出本关并处理未保存操作。操作前建议关闭其他载具页面。文件上限 4 MiB，损坏 / 未来版本的文件或当前档案均不会被自动修复、降级或清空。

### 本战役安全节点

- 从先遣队入口开始第 2 / 4 关，到达已有安全节点时自动保存到先遣队独立档案。
- 失败、退出本关或刷新后，使用 **“从先遣队安全节点继续”**，二次确认后恢复。
- 按原安全模板重置载具；不会从 JSON 恢复任意坐标或速度。敌艇重置、起步缓冲、联合任务安全停放规则沿用原实现。
- HUD 和记录明确显示“检查点继续”。成功后推进下一关，但不计入完整一命次数或最好用时。
- 选择从关首重试时，旧节点保留到到达新节点；新建另一战役则清除当前节点、保留历史通关记录。
- 原“南湾 / 联合安全检查点”面板仍是**单项模式**。从那里恢复不会接管先遣队所有权，也不能推进先遣队。
- 第 1 / 3 关没有新增关内模板，仍从关首重试。本批没有实时位置存档或空中存档。

## 3. 资格与隔离矩阵

| 来源 / 结果 | 推进先遣队 | 记录口径 | 原单项节点 |
| --- | --- | --- | --- |
| 先遣队从头完整通关 | 是，事务提交后 | 完整一命，可更新该任务 / 难度最好用时 | 不写入、不清除 |
| 先遣队所属节点恢复后完整通关 | 是，事务提交后 | 检查点继续，独立计数，不更新完整一命最好用时 | 不写入、不清除 |
| 原单项按钮 / 原单项节点恢复 | 否 | 沿用原单项规则 | 原行为保留 |
| 失败 / 中止 / 换模式 | 否 | 不产生通关记录；已提交的本战役安全节点保留 | 各自隔离 |

成绩仍按实际任务规则分组：第 1 / 2 关锁定所选难度，第 3 / 4 关是固定规则。跨关可刷新，不提供全战役一命排行榜；档案为本地自管数据，不声称服务器认证或防篡改成绩。

## 4. 存储、兼容与故障边界

- 档案受浏览器配置和游戏站点来源（域名 / 端口）隔离；更换地址不会自动搬迁。专用 JSON 只导出当前来源已提交的先遣队档案，可用于主动迁移。
- 数据库仍是 `neon-eclipse.expedition.v1`，物理 IndexedDB 版本 1，复用现有单行 CAS 存储接口（档案位于 `checkpoint` 字段）；没有数据库删除、批量清空或跨库事务。
- 档案 payload 升为 schema 2，任务规则仍为 `front4-v1`。增加当前节点与一层 `undo`；旧完整一命记录保持 schema 1，新增恢复记录使用 schema 2 / `resumed:true` 与恢复起点摘要。
- 读取、展示、导出旧 schema 1 不会偷偷写回。第一次实际的新建 / 保存节点 / 结算 / 不同内容导入才提交新格式。
- 旧版本页面读写新 payload 会拒绝未知版本而非降级覆盖；需刷新旧页面。未知未来数据库 / payload、损坏行和权限拒绝均保留原数据。
- 节点绑定战役 ID、拥有的尝试 ID、当前顺序任务及锁定难度；只允许海战 / 联合的已知节点名，不能跨战役、跨任务或跨难度恢复。
- 自动节点保存与随后到来的结算串行处理。后续操作在前一事务真正提交后归约，避免结算在保存期间丢失；未提交不会提前解锁下一关。
- 进度推进、通关记录与当前节点退役同事务提交。导入结果与替换前快照也同事务提交；成功 put 后事务中止，仍整体回滚。
- 每个待提交意图固定操作 ID 和首次尝试的内容；确认丢失后重试不重复生成修订。并发 CAS 冲突不自动采用 / 覆盖别人版本。
- 相同内容导入是带修订检查的只读 no-op，不更新撤销副本。预览后的文件对象变化也不会改变已准备的替换内容。
- 1000 条通关记录上限保留，计入完整一命和恢复记录，不自动淘汰历史；尚无容量清理面板。
