# Boss 二阶段、武器动作与高架运输：本轮交付及后续路线

## 1. Boss 血条与第二阶段

- 顶部中央新增明确的渐变生命条、当前生命 / 480 和阶段名称，避免覆盖右侧武器卡片。
- 核心生命降到 240 或以下时进入第二阶段。当前暴露窗口继续有效，不会在半血时突然吞掉玩家伤害。
- 第二阶段将单向电弧升级为四方向交叉电弧，预警仍为 1.5 秒，释放 0.55 秒，休止缩短到 1.4 秒，每次命中至多 22 点伤害。
- 四条预警带与真实伤害方向一致，方向锁定后不追踪；可走向交叉带之间的空隙、跳跃或利用掩体。每次释放最多命中玩家一次。
- 节点、8 秒核心暴露和地面高压互斥保留。暂停冻结、重试复位，击败后不残留攻击。

## 2. 动作

- 步枪、手枪增加可移动弹匣和取出 / 装回路径；支撑手随动作移动，枪机和套筒有回拉动作。
- 喷子保留逐发装填，完善弹壳送入和支撑手位移。动画使用实际装填进度；装弹数仍由原有装填规则决定，不提前转移弹药。
- 近战改为蓄势、挥砍、回收。实际伤害延迟到起手后 0.19 秒，而不是按键瞬间扣血；切枪和重试取消未触发的挥砍伤害。
- Shift 冲刺时双手持枪向胸前收拢并倾斜，叠加步伐驱动的上下、左右和旋转抖动；停止冲刺平滑回位，空中不继续脚步抖动，不给相机额外添加抖动。
- 本轮是程序化动作完善，不是骨骼绑定、完整手指 IK 或最终动画资产。

## 3. 高低差与运输平台原型

第三章东侧阵列新增可实际使用的高架检修区，不是背景摆件：

- 入口楼梯位于约 `(20, 5)`，向东上行，经 12 级、每级 0.25 米的台阶到达 3 米高架平台；无需连续跳跃上楼。
- 高架平台中心约 `(30, 5)`，另一处检修泊位约 `(32.5, 16)`。
- 青色运输车台地面停靠位置为 `(35, 5)`；站上车台即可自动乘坐。
- 每 36 秒循环：地面停靠 → 升至 3 米 → 高架停靠 → 水平驶向检修泊位 → 返回 → 下降。水平行程 11 米。
- 车台真实承载玩家，暂停冻结；玩家可以步行或跳跃离开。上方净空不足或承载移动会把玩家推进实体时，车台停止而非继续挤压。
- 检查点增加可选 `transportTime`，与已有脚部高度一起恢复车台和站立位置。旧检查点没有该字段时从车台起点恢复；没有另建自动实时存档，仍沿用阶段入口检查点语义。
- 新结构加入实体与射线障碍物。修正了第二阶段一个与高架结构冲突的固定出生点，避免出现“没有足够安全出生点”异常。

### 明确边界

本轮完成的是高低差和升降 / 水平运输载具的可玩原型，不是全部载具系统。尚未实现：

- 地下运输站真实行驶的列车、可驾驶车辆、上下车交互和车门联动。
- 敌人上楼及跨层寻路。敌人仍沿现有地面导航移动；不把玩家可上楼描述为敌人也能上楼。
- 平台边缘完整护栏、安全门、摔落伤害，以及运输区专属战斗任务。

## 4. 验证

远端 `npm test` 全部通过；编辑器诊断没有错误或警告。

新增 `test-expansion.mjs` 覆盖二阶段交叉伤害、动作进度、延迟近战触发、楼梯上下行、平台升降与水平承载、暂停、跳跃脱离、位置恢复、顶部防挤压及新结构与固定出生点的兼容性。

另将远端当前源码复制到隔离沙箱，用 Chromium 实际加载 Three.js 场景进行受控回归：

- 核心从 480 降到 230 时，UI 显示第二阶段，血条约 47.92%。
- 在真实屋顶场景从地面步行到高架，脚部高度达到 3 米。
- 站在运输车台上随车升高并移动到 z=16，读取检查点后高度、位置和车台时钟一致。
- 冲刺时枪械进入胸前倾斜姿态；装填过程中弹药保持不变，完成时转移弹药。
- 近战起手后 0.1 秒 Boss 仍为 480，0.2 秒时降为 385，验证真实伤害延迟。
- 页面 JavaScript 异常为 0。

上述是受控清敌、推进时间和操作状态的测试，不是完整人工战斗通关；也不是用户 Windows 机器的帧率测试。运行中的临时调试接口仅通过测试服务器注入，未写入生产 `app.js`。

## 5. 后续开发方向

1. 高低差闭环：为静态楼梯建立跨层导航连接，让敌人能上楼、下楼并正确处理不同高度的射线和攻击；检查高架是否形成可无风险清敌的位置。
2. 运输体验：补护栏、安全门、呼叫 / 出发按钮、停靠提示，验证多人型敌人或动态物体靠近车台时的碰撞；把运输区接入任务而不只是自由体验区域。
3. 真正移动列车：复用承载与检查点时钟，先实现车厢内玩家随行、车门与站台碰撞，再做列车抵达和撤离流程；不要只移动背景。
4. Boss 与动作精修：击中音效、节点爆裂、核心过载和击败演出，完善手部衔接与武器材质。
5. 完整三章人工试玩与实机性能：记录死亡点、弹药余量、通关用时与帧时间，完成平衡和性能预算后，再考虑第四章。
