### 1.3 优势（应保护）

1. 规则层与渲染层分离良好（`*-rules.js` 纯函数 + `*-world.js` 场景 + `*-ui.js`），便于测试与扩展。
2. 明确的"可读预警"战斗语言：颜色 + 锁定线 + 窗口，是差异化基础。
3. 严谨的存档兼容与"不伪造状态"文化（损坏不覆盖、失败可重试、测试隔离存储）。
4. 载具物理已有多帧率一致性验证（30/60/120/144Hz）。

### 1.4 主要风险

- `app.js` 与 `vehicle-app.js` 继续膨胀会让第七章成本非线性上升。
- 无 Git 意味着任何一次误改都无法回退；这是所有后续工作的前置项。
- 音频缺失会在试玩反馈里被放大为"廉价感"，其性价比远高于再加一张地图。
- 挑战难度（纯刀/无伤）缺少真人数据，调参只能靠猜。

## 2. 愿景与设计支柱

**一句话定位：** 一款"可读战斗 + 陆海空换乘"的霓虹战术射击游戏，单人为主、可重玩为辅、全部程序化资源、浏览器即开即玩。

设计支柱（后续所有功能按此取舍）：

1. **可读性优先**：任何攻击都有颜色/形状/时序预警；死亡必须能归因。
2. **换乘即玩法**：步行、驾驶、航行、飞行不是切场景，而是同一世界内的连续动作。
3. **诚实的进度**：成就、成绩、难度标签绝不伪造，读档/训练不等于合格。
4. **程序化美学**：不引入外部贴图/模型/音频依赖，全部由代码生成或合成，保持 0 CDN。
5. **小步可回归**：每个功能都有纯规则测试 + 至少一条浏览器路径。

## 5. Phase 1｜战斗深度

### 5.1 近战：从单射线到"短弧体积扫掠"

现状：`combat.js` ARC BLADE 距离 3.5、单射线、`melee-sweep.js` 已有采样框架。

方案：
- 在 0.42s 动作的 28%～58%（strike 段）内，每帧沿水平 ±35° 弧、垂直 ±15° 做 5×3 采样射线，取首个未被墙体遮挡的命中；同一挥砍内每个敌人只结算一次（`hitSet`）。
- 命中判定"手感补偿"：目标在 3.5m 内且角度在弧内即使中心射线未命中也算命中；超出 3.5m 即使中心射线命中也不算（保持距离诚实）。
- 新增**处决**：对 HP 低于 15% 且处于硬直的常规敌人，近战触发 0.6s 处决动作，无敌帧 0.3s，回复 8 HP。为纯刀挑战提供节奏奖励而不降低难度。
- 新增**格挡/弹反**（可选，Phase 1 后半）：持刀时右键 0.25s 窗口弹反橙色（突击）弹体，反射回敌人；紫色/琥珀色不可弹反。给刀一个防御维度。
- 测试：贴身、边缘、掩体侧、切枪中断、暂停恢复、120ms 大帧间隔、Boss 核心/节点可达性。

### 5.2 武器体系扩展（数据驱动）

`combat.js` 的 `WEAPONS` 扩为 `weapons/` 目录，每把武器一份数据 + 可选行为钩子。目标 8～10 把，分四类各 2～3 把，玩家携带 **主武器 ×1 + 副武器 ×1 + 近战 + 投掷物 ×1**（替换现在的四把全带，增加选择）。

## 6. Phase 2｜音频与表现

### 6.1 音频架构（零外部资源）

新建 `audio/`：

```text
audio-bus.js       主/音乐/音效/UI/语音 五总线，独立音量，暂停时 suspend
synth.js           程序化合成器：噪声（枪声/爆炸/雨）、FM（能量/电弧）、脉冲（UI）、采样级混响卷积（程序生成 IR）
sfx-catalog.js     事件→合成配方映射：fire.vanguard / hit.flesh / hit.armor / reload.shell / melee.swing / enemy.telegraph.orange …
spatial.js         Three.js PositionalAudio 包装：距离衰减、遮挡低通（墙后 −12dB 高频）、多普勒（载具）
music-director.js  状态机：探索 / 遭遇 / Boss 阶段 I-III / 撤离倒计时 / 胜利 / 失败；分层轨道（鼓/低音/合成主旋律）按强度淡入淡出
voice.js           HUD 提示"语音"：用短合成音节 + 字幕替代真人配音（保持程序化）
```

- 程序化合成每个音效的配方以 JSON 参数描述，可在设置页"音频实验室"试听。
- 可选扩展：支持用户放置 `audio-pack/` 目录覆盖配方为真实采样（不作为默认依赖）。

### 6.2 音频作为可读性通道

- 每种敌人预警都有专属音高与节奏（橙 = 短促双音、紫 = 上滑锁定、琥珀 = 低频三连、金 = 长鸣）。
- 方向性：敌人在背后开火时声像 + HUD 边缘指示器双通道。
- 近战命中/处决/弹反各有明确音效；霰弹逐发装填每发一个"咔哒"。
- 载具：引擎转速对应油门（锯齿波 + 低通）、飞机失速警报、船体波浪拍击。

### 6.3 天气与时间

`weather.js`：晴 / 雨 / 雾 / 沙尘 / 夜 五种预设 + 强度 0～1；影响能见度（雾 = 远程锁定距离 −30%）、地面反射、粒子。每章默认预设 + "挑战修饰符"（见 Phase 4）可随机。

### 6.4 击杀与命中反馈升级

- 命中：按部位（头/核/装甲）差异化粒子颜色与准星反馈形状（现有基础上加音效）。
- 击杀：轮廓闪白 + 溶解 0.4s；精英/Boss 慢动作 0.3s（可关）。
- 连杀：3/5/10 连杀 HUD 短提示 + 音乐层级 +1（不加数值奖励，仅表现）。

### 6.5 过场与叙事（轻量）

- 章节开场 8～12 秒：镜头飞掠 + 三行文本 + 目标卡；可跳过。
- 章节间"简报屏"：上章战报摘要 + 下章威胁预告，由数据驱动，不写死。
- 世界叙事通过可拾取的"数据碎片"（每章 3 个）呈现，收集进成就页的"档案"。

### 6.6 Phase 2 验收

- 所有战斗事件有音效；音频总线可独立静音；暂停/失焦 suspend；无 AudioContext 未经用户手势报错。
- 音乐状态机在 Boss 三阶段与撤离倒计时切换正确（集成测试驱动状态、浏览器测试验证 `AudioContext.state`）。
- 天气不改变碰撞与判定，仅改变能见度参数（测试保证）。

- 辅助选项（不计入成就）：无限弹药、伤害减半、时间 70%。

### 10.3 本地化

- 文案抽离到 `i18n/zh-CN.js` / `i18n/en.js`；HUD 与菜单动态切换；先 zh-CN + en。

### 10.4 性能验收

- 目标：1080p 均衡档在中端核显 ≥ 60fps，1% low ≥ 40；精细档独显 ≥ 120。

- 自动降档：连续 3s 帧时间 > 22ms 提示切换画质（不自动切，尊重用户）。

### 10.5 发行准备（仅在用户明确要求时执行打包）

## 11. 横切系统设计

### 11.1 统一难度框架

```text
difficulty-core.js
 ├─ profiles: { easy, normal, hard, [nightmare 预留] }
 ├─ domains: combat（已有）/ naval（已有）/ vehicle / boss / economy
 ├─ resolve(domain, param) -> multiplier
 └─ lock(session) -> 不可变快照，写入成绩标签
```

现有 `combat-difficulty.js`、`naval-settings.js` 作为两个 domain 接入，不改数值。

### 11.2 存档架构 v5

- 不做"大迁移"，SaveHub 之上定义 `journey.v5`：新增章节数组按注册表顺序、每章 `{cleared, best, difficulty, stars[], fragments[]}`；v4 → v5 迁移测试沿用现有模式。
- 备份文件格式：`{app:'neon-eclipse', schema:1, exportedAt, slots}`；导入校验 schema 与每槽 validate。

禁止无数据"拍脑袋"调 Boss 血量。

## 13. 风险与"不做"清单

| 风险 | 缓解 |
| --- | --- |
| 大重写导致回归 | 注册表/SaveHub/拆分均为并存渐进；每步 L3 |
| 内容扩张超出程序化美术承载 | 每章限定 1 种新材质风格；复用部件库 |
| 音频合成听感廉价 | 先做可读性（区分度），再做质感；预留采样包覆盖 |
| 载具流式与 FPS 章节耦合 | 流式只用于试验区/先遣队；六章保持静态 |
| 模式过多稀释打磨 | Phase 4 先做生存 + 修饰符两个，其余按试玩反馈 |

明确不做（除非用户重新决策）：联机多人、云存档/服务器排行榜、真实 IP 授权素材、付费内容、移动端完整驾驶、手动制作 EXE（保持只交付源码）。
