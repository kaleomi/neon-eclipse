### 实际接入方式

- `mission-prop-models.js` 是游戏和 GLB 导出的共同建模源。静态几何按材质合并，避免每个螺栓一个绘制调用。
- 游戏 `mission-world.js` 同步使用同源程序模型；**本批没有给游戏增加异步 GLB 加载器**。独立 GLB 用于交付、预览和其他 DCC 使用，不虚称生产页已请求这些 GLB。
- 模板最多三类，实例只共享不变几何/材质，变换各自独立；拾取与重试不释放共享资源。
- 医疗/弹药标志沿用 `supply-symbols.js` 的轮廓与颜色；浮动位置、世界标牌、拾取高度、距离、满资源拒绝、收集/恢复语义不变。
- 终端保留原 `1.8 × 1.4 × 1.0` 碰撞/射线网格，仅将其材质隐藏；新视觉不参加射线测试。原任务 Canvas 屏、状态灯、位置、朝向和更新逻辑保持。独立 GLB 不固化任务文本，因此展厅终端屏是待运行时填充的暗屏。
- `mission-props-preview.html` 是项目内三维展厅：切三模型、GLB/同源程序对照、正背面、线框、缩放及单模型下载。通过原 `node server.cjs` 服务访问，不修改服务器配置。

### 保留的首轮问题

1. 终端屏幕边框上沿比旧碰撞包络多 5mm，边界断言捕获后缩回 1.4m 内，并重建通过。
2. Three.js 克隆经过 quaternion→Euler 产生约 2e-16 的标志角度差，旧精确断言捕获。克隆后恢复顶面标记的规范角度，原测试不变并通过。
3. 独立 Khronos 格式检查最初出现 14 条无效零发光强度扩展警告（0 错误）。将无发光材质保留默认强度 1，因 emissive 仍为黑色，不改变渲染；随后重建并重新检查。
4. 材质清理后的第二轮浏览器测试在 390px 断言失败：renderer.setSize 默认写入旧的内联像素宽度，ResizeObserver 回调前会短暂溢出。改为 setSize(width,height,false)，保持 CSS 的 100% 响应式宽度；原断言不放宽。
5. 宿主在浏览器运行期间两次新 PTY 启动未能在 8 秒内到达提示符；没有重复启动浏览器重负载。首次资产传输遇到终端长行折行丢字符，改为 60 字符分行并以清单 SHA 校验成功；未将不匹配副本作为交付。

最终格式复核、材质清理后复跑以及诊断结果记录在下节。浏览器采用隔离 Chromium + SwiftShader，只是自动化渲染/启动证据，不是自然通关、全部武器射击或实机性能证明。
