## 结论

九章旧档只读迁移、连续战役写入失败不推进、重复结算拒绝，以及先遣队进度/节点/成绩隔离的所选规则测试通过。本轮实际修复集中在 **FPS SaveHub** 的读取、导入和撤销故障边界；没有改写先遣队 IndexedDB 实现或章节存档模型。

单章检查点在持久化失败时保留本页内存状态供重试，是既有设计；`persistent=false` 与 UI 明确提示“关闭页面后无法恢复”。本轮保留它，没有错误地将其改成连续战役的“写入成功才推进”模式。

## 修复范围

| 故障 | 原行为风险 | 修复后 |
| --- | --- | --- |
| 槽位读取抛错 | 被当作不存在，可能生成缺项备份或错误显示空档 | 健康状态为不可用；导出/快照拒绝，预览报不可用，导入前备份不完整则停止且不写入 |
| 撤销恢复部分写入失败 | 仍将备份替换成当前状态，原恢复目标丢失 | 任一槽位失败时保留原恢复目标，故障消除后可再次尝试 |
| 原槽位是损坏 JSON | 通用导入校验跳过它，撤销后没有回到原始字节 | 内部撤销按原始字节恢复已登记槽位；外部导入仍校验、仍跳过损坏项和未知键；不是修复损坏数据 |
| 撤销成功写入槽位、但保存反向备份失败 | 异常被吞掉，返回整体成功 | 返回 partial，列出备份写入失败，原恢复目标仍保留；不声称已经回滚变更 |
| 等待异步飞行成绩时重复点击导入/撤销 | 第二个操作可覆盖首个操作的前镜像 | 同一 SaveHub 实例使用互斥标记；重叠操作返回 busy；完成/失败后释放；外部 writeBackup 在忙时拒绝 |
| 飞行成绩保存返回失败或抛错 | 仅以槽位结果判定成功，或 Promise 直接拒绝 | 单条异常计入 failed，继续汇总；成绩失败同样使总体结果为 partial，UI 显示失败数 |
| 大小/序列化边界 | 按 JS 字符串长度而非字节限制，循环对象可能抛出未处理错误 | 导入按 UTF-8 字节数限制 4 MiB；序列化失败返回 invalid，均在写入前拒绝 |

另外，飞行成绩导出读取抛错时，备份带明确的 `flightRecordsError`，不冒充包含该部分。修改文件为 `save-hub.js`、`save-hub-ui.js`；新增测试为 `test-save-stability.mjs`。

## 必须保留的限制

1. **FPS localStorage 多槽位不是原子事务。** partial 可能意味着一些槽位已经改变；本批保证如实报告，并在恢复失败时保留恢复目标，不伪造“所有数据已自动回滚”。
2. 撤销只有一层备份。部分恢复后再尝试成功时，反向备份是该次重试前的状态，不承诺自动回到首次失败前的完整状态；操作前应另外导出 JSON。
3. `mutating` 是同实例互斥，不是不同标签页/不同 SaveHub 实例之间的分布式锁。先关闭其他游戏页面，再做导入/恢复；跨页一致性仍需单独设计和原生验证。
4. FPS 与先遣队仍使用不同备份文件和独立分区；FPS 的撤销不撤回已另行写入的飞行成绩，不操作先遣队数据库。
5. 只验证内存故障路径与规则，未完成文件选择/下载 UI、实际浏览器配额、六处节点真实接线或真人九章/四关验收。S1/S5/S6 保留人工待办。
