# 从参考游戏借鉴流程：第一轮落地

参考地址：https://apps.gamesvibe.app/2/

## 看到了什么

检查了公开菜单、章节选择、页面实现，并抽样进入第 1、4、5、14 章，进行了短时移动与画面/HUD观察。不是完整通关，也没有完成其全部机关或载具路线。章节选择实测为 20 个入口；抽样页面没有 JavaScript 异常。

最值得借鉴的不是把界面改成同样的橙色，而是任务组织：

- 章节各自构建场景、目标、敌人、道具和触发器；完成后清场并进入下一章。
- 车站开场采用非战斗引导和角色字幕，随后以交互、奖励、离开区域推进。
- 运河/道路载具改变移动节奏；工具教学、投掷目标和反应堆插槽改变操作方式。
- 章节标题、始终可见的当前目标和简短对白，让玩家知道去哪里、为什么去。

其源码中可见章节号写入存储，但本轮没有验证刷新后继续完整流程，不能把菜单里的“继续”按钮等同于已验证的持久存档。也没有测量其资源回收或暂停期间脚本事件是否存在问题。本项目不复制其代码、品牌、人物、对白或地图。

## 我们的真实差距

现有项目的枪械、可躲避弹丸、三类守卫和 Warden 阶段战已经具备可测试规则，但流程主要发生在同一个 80×80 场地，前三个目标此前都是清场后站定按 E。

参考游戏在章节数量、场景变化、载具和工具玩法的广度上仍明显领先。本轮没有新增地图，不把五阶段训练入口称作五张新地图，也不宣称已经全面超过参考。

## 已实现

### 1. 真正可恢复的阶段检查点

- 新行动开始、进入下一阶段时记录阶段入口检查点。
- 保存当前阶段、生命、三种枪的弹匣/备用弹药、当前武器、位置/朝向、计时、击破数、已消耗补给。
- 实际刷新页面后，在菜单点“继续检查点”恢复。死亡后点“重试本阶段”；暂停菜单也可重置本阶段。
- 保存的是阶段入口，不是战斗中逐帧快照。刷新或重试会重建该阶段敌人；上传中断后重试也从访问权限阶段入口重新开始。
- 保存于当前浏览器、当前站点的 localStorage，键为 `neon-eclipse.campaign.v1`。换浏览器、换访问地址或清理网站数据不会自动同步。
- 对版本、阶段、位置、资源上限和补给 ID 做校验。存储被禁止或空间不足时仍可游戏，并保留本页面内的重试数据；菜单明确提示不能跨页面恢复。
- “开始新行动”会替换当前行动检查点，但保留已解锁训练阶段。完整撤离后清除当前检查点并保留全阶段解锁。

### 2. 阶段训练

五阶段随主行动推进解锁；已解锁阶段可单独训练。训练使用标准生命/弹药与阶段入口，完成所选阶段后结束。

训练不会覆盖主行动检查点，也不会代替主行动解锁后续阶段。训练结束或暂停时可返回已有主行动检查点。

### 3. 原创无线电文字引导

加入 LINK-7 中继员的五段简短字幕，说明冷却、权限、解锁、核心弱点与撤离之间的因果。字幕使用游戏时间，暂停时冻结，不通过墙钟定时器推进剧情。本轮是文字引导，没有语音配音。

### 4. 访问权限：启动上传 → 持枪防守

1. 清除原有东侧守卫。
2. 面向终端，站定按住 E 2.5 秒启动上传。
3. 出现三名增援，上传需要累计 25 秒。
4. 留在终端 12 米内即可上传，无需继续按 E；可以移动、射击、瞄准或换弹。
5. 离开范围会暂停累计，返回后继续；受击不会清空上传。地图显示琥珀色边界，终端屏幕切换为防守提示。
6. 上传达到 25 秒且增援全部消灭后取得权限。计时结束但仍有敌人时不能跳过战斗。
7. 按 Esc 会冻结战场和上传计时。

本轮基础守卫仍为 26 个，上传增援另加 3 个，总计 29 个目标（含 Warden）。未增加阶段自动回血/补弹。

## 验证

`npm test` 包含语法检查及五组纯逻辑测试：碰撞/导航、枪械、任务/补给/上传防守、敌人/Boss、检查点。

本地 Chromium 受控回归验证了：

- 真实刷新后恢复阶段、85 点生命、指定弹匣/备用弹药、当前武器和已用补给；正确重建阶段敌人。
- 上传开始增援、移动射击同时上传、出圈暂停、受击中断接口不重置上传、计时结束仍等待清敌。
- Esc 冻结上传；阶段训练不改变主行动存储；受到致命弹丸伤害后可读取入口重试。
- 完整流程仍需撤离，训练完成不算全行动完成；完成后的解锁可跨刷新保留。
- 浏览器拒绝 localStorage 时可进入游戏并在本页面重试。
- 原有任务、枪械、敌方弹丸、装甲/核心结算和 Warden 阶段回归通过。

这些测试包含受控位置、清敌和时间推进，不是完整人工通关。新增增援后的弹药需求、25 秒上传是否过长、一局总时长，以及 Windows 真机帧率仍需试玩。参考游戏也未完整通关，不能据此作全面性能或品质排名。

## 下一轮：第二张原创“地下运输站”（尚未实现）

建议做一张短但完整的线性地图，而不是把当前场地换颜色：

**维护入口（安全引导） → 配电室（恢复供电） → 站台（中距离交火） → 车厢（近距离穿行） → 调度室（切换道岔） → 末班列车（撤离）**。

下一步需把当前阶段管理扩展为真正的地图/章节加载，区分走廊、站台和车厢的空间尺度，引入与环境相关的交互，再验证检查点和旧场景资源清理。评价“超过”的标准应包括玩家是否迷路、任务是否重复、死亡后损失是否合理、实机是否流畅，而不只是增加章节数字。
