- 检查 Warden、枢纽监察者和港口精英的暴露窗口能否被正常近战利用。
- 优先调整预警、贴身空间、命中反馈和遭遇组合，而不是仅堆血量或无依据削弱难度。
- 结合阶段承伤、耗弹、死亡位置与窗口利用记录，定位港口末批压力、楼梯拥堵、补给余量问题。

验收：动画与命中反馈一致；不会隔墙砍中或一次挥砍重复伤害；挑战资格和旧存档不回归；新增判定测试与浏览器集成验证均通过。人工挑战可达性另行记录，不用注入结算替代。

### P1：实机性能与长时间运行

- 在目标 Windows 设备逐章采样三档画质的帧时间、1% low、内存趋势和场景绘制统计。
- 重点关注港口雨雾与增援、列车环境运动、多层关卡的敌人导航。
- 找到瓶颈后再优化粒子更新、阴影范围、绘制批次、临时对象和 UI 更新频率。
- 是否增加自动降档、更多后处理，由实测数据决定。

验收：先确定目标设备、分辨率和目标帧率，再用同一场景的前后数据比较；不以无头截图中的 FPS 作结论。

### P2：存档可靠性、维护性与发行准备

- 增加可选的战役/星星/成就本地备份与恢复，明确区别于战斗报告导出；导入前校验版本、保留备份并确认覆盖。
- 补充项目 README、运行要求、操作说明、已知限制与统一测试入口。
- 在相关功能迭代时逐步拆分 `app.js` 的输入、会话/存档、战斗和地图接入职责；将地图选择收敛为注册表/适配层，不做无必要的大重写。
- 统一六章文案，给旧路线文档注明历史状态。

### P3：再扩展内容，而非先增加地图数量

优先给现有章节增加有辨识度的机制：列车隧道/限高预警事件、列车或中枢塔专属精英、任务完成后的场景反馈、空间音效和更明确的 Boss 击败演出。成就徽章、称号与筛选可作为较小规模的可见增量。

第七章应在前述基线稳定后确定独特玩法与内容预算，避免再次复制“清敌 → 按 E → 防守 → 撤离”。云同步和联机属于独立大功能，不应夹带进入一次手感修复。
