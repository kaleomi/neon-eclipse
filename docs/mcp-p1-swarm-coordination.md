# MCP P1 第八批：蜂群照明与远程协作

## 交付范围

已接入主线源码，未制作 EXE。本批承接反应堆的六机蜂群试点，新增冻结位置共享、可中断照明、远程搜索与协作起手预算，没有扩大投放章节，也没有改伤害、射速、星星路线、视角输入或港口难度。

原反应堆解除封锁阶段仍为 7 守卫 + 6 编队型无人机；当前其他章节、旧 drone/sniper/shield/stalker 和八种玩家武器保留。本批只选择 `ranged` 为接收者，不把狙击手或其他敌人自动编入协作。

## 信息共享与可读反制

- 只有蜂群成功排入一轮有真实视线的蓝色预警，才发布观察结果；没有按每帧玩家坐标持续广播。
- 选择信息源 18m 三维范围内最近、仍存活的最多两名远程守卫。信息是深拷贝位置快照，接收者之间不共享可变坐标引用。
- 照明状态最长 1 秒，共享位置最长 3 秒，均按游戏时间计时，暂停冻结。
- 玩家离开观察点 1.25m 范围，或信息源与玩家之间出现遮挡，照明立即中断；当前记录不会因玩家走回来而重新点亮。已经观察到的旧位置仍按原期限失效，不变成隔墙追踪。
- 信息源被击落或移出敌人列表，立即清除它发布的共享信息；接收者死亡、离开列表或超出通信范围会退出接收。另一架无人机以后成功开始新预警时可以发布新的独立记录。
- HUD 区分“蜂群照明共享 → N 名远程”与“远程搜索旧位置 / 剩余秒数”，明确横移断照明、击落断共享；接收者的敌人检查器显示共享旧位剩余时间。

照明采用既有蓝色瞄准线/蜂鸣配合新增 HUD 状态表达，不是新增体积探照灯或全图视觉透视效果。信息共享不增加射程、伤害、命中率或冷却增益。

## 远程守卫行为

- 接收共享且自身看不到玩家时，朝向和导航使用固定的旧位置；不会继续从这份信息获取玩家实时坐标。
- 接收者自己重新看见玩家时，自己的真实视野优先，更新本人的最后可见位置。
- 共享失效后，不再使用共享坐标；如果守卫有自己的最后可见位置，可继续搜索那里，否则原地等待重新获得视线。到达搜索点附近停止推进，不因共享信息穿墙追踪。
- 发射仍需要本人的射程、真实 LOS、朝向、冷却及攻击起手许可全部满足。共享位置绝不是隔墙开火授权。
- 击落蜂群信息源不是眩晕守卫或清除其自身视野：它仍可能基于自己看到的玩家正常攻击。

仅被当前协作选中过的接收者启用这套搜索行为，并在本次遭遇内保留公平的失去视线处理。未参加协作的旧敌人保持旧逻辑，重置时清理接收标签和本人视野缓存。

## 协作攻击预算

在上一批“全蜂群最多一份待发或飞行弹体”之外，增加蜂群与参与协作的远程守卫合计最多两份待发/在飞威胁。

- 新蓝色起手或协调远程起手需在没有其他待发预警且合计威胁少于二时开始。
- 协调远程开始预警后，旧全局起手 gate 延长至覆盖该次预警，避免刚开始一轮预警就叠第二轮。
- 已发射弹体继续占用预算，不因信息源或接收者死亡立刻释放数量限制。
- 该限制针对协作子队伍，不宣称全场所有敌人的飞行弹体都上限为二；其他地面角色、Boss 的既有规则保持。

`projectiles.js` 增加只读 `countThreatTag`，不改变弹体伤害/速度/碰撞。敌人 LOS 每次更新读取当前障碍列表，避免协作检查持有已经过期的障碍集合；此项由真实障碍移除后的重新获得视线测试覆盖。

## 生命周期与存档

共享信息、接收标签、协作预算均是运行时状态，不新增存档字段或版本。检查点重试重建原阶段编队与守卫，不继承旧坐标、照明或待发攻击，不恢复严格纯刀资格；武器弹药协议不变。

重置与结算调用 director 清理，暂停只冻结而不清除。浏览器已通过真实 RAILSPIKE 蓄力射击，击落正在发布信息的无人机，确认待发攻击及接收信息同时中断。
