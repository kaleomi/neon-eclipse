# 反应堆夺回行动：任务、补给与导航

## 本轮范围

将原有自动五波生存循环替换为线性区域任务，不再清波后自动恢复生命和弹药。保留 80×80 地图、四种武器、敌方可躲避弹丸和现有战斗反馈。8–12 分钟是设计目标，尚未通过完整人工通关标定时长。

## 完整流程

| 阶段 | 位置 | 守卫 | 完成条件 |
| --- | --- | --- | --- |
| 西侧冷却 | (-28, 0) | 5 | 清敌，按住 E 2 秒启动装置 |
| 东侧权限 | (28, 0) | 6 | 清敌，按住 E 2.5 秒下载权限 |
| 反应堆控制台 | (0, -11) | 7 | 清敌，按住 E 3 秒解除封锁 |
| Warden | 中央反应堆附近 | Boss + 3 护卫 | 击破 Boss 与所有护卫后自动进入撤离阶段 |
| 南部撤离 | (0, 32) | 4 | 返回信标、清敌，按住 E 3 秒撤离 |

终端交互要求距离不超过 2.8、站定、不射击、不换弹、面向目标且无遮挡。撤离信标无需低头瞄准。松开 E、离开范围、开始射击/移动或受击会中断进度；暂停冻结游戏，恢复后需重新按住 E。不能跳过前置阶段，击败 Boss 本身不判定胜利。

阶段切换清理旧弹丸，并根据当前目标挑选附近、安全、不重叠的敌人出生点，距离玩家至少 14。三个实体终端加入碰撞与寻路数据。死亡重开重置任务、计时、敌人、补给、弹药和交互状态。

## 补给

地图放置四个医疗箱和四个弹药箱，靠近 1.65 范围自动拾取。医疗箱最多恢复 35 生命；弹药箱为步枪/霰弹枪/手枪分别增加 60/16/30 备用弹药，不直接装填弹匣，并遵守原有备用弹药上限。满状态时保留箱子，成功拾取后本局不刷新，重新部署后恢复。

## 导航与界面

- 左侧五阶段任务清单与行动计时。
- 场景目标标记、距离和离屏方向提示；Boss 阶段跟随实际 Boss 位置。
- 近距离交互说明、清敌要求和进度条。
- 宽屏小地图显示当前区域目标、剩余医疗/弹药箱。
- 终端编号和指示灯、悬浮补给箱、南部撤离信标；延续青橙工业科幻风格。
- 结算显示撤离结果、击破数量和游戏内行动用时。

## 模块

mission.js：阶段定义、纯状态机、补给规则和出生点选取。
mission-world.js：终端、补给和撤离信标。
mission-ui.js / mission.css：任务追踪和导航。
app.js：战斗与任务衔接；radar.js：目标及补给标记。

## 验证

test-mission.mjs 覆盖前置任务门控、交互中断、五阶段/撤离/重置、补给上限、26 个实际阶段出生点及终端加入后的大型敌人通行路径、全部补给位置可达性。原有地图/弹道几何和武器逻辑测试继续通过。

独立 Chromium 测试通过：满状态不消耗箱子、医疗恢复和弹药拾取、无重复领取、敌人未清不得交互、不能先操作东侧、真实视线交互、松开/受击中断、暂停冻结、五阶段依次推进、Boss 与护卫生成、撤离前不提前胜利、胜利与重新部署重置。完成了菜单/射击/换弹/开火方式/敌方弹丸回归，页面 JS 异常为 0。检查了宽屏实战截图并修正导航标记遮挡任务栏的问题。

浏览器流程通过测试钩子控制敌人清理和玩家位置，不等同完整人工射击通关；Windows 实机性能、难度、路线时长仍需试玩验证。已有服务时 Ctrl+F5 刷新 http://localhost:5173；否则项目目录 npm run dev。npm test 包含语法及纯逻辑测试。
